# 03: 渲染棋盘并接入游戏循环

**What to build:** 将纯游戏规则接入浏览器，新增职责单一的 Canvas renderer 与可注入调度器的 runtime/controller，实现开始、固定节奏推进、画面与分数状态同步、暂停/继续及 game-over 后停止，并保持 `main.js` 仅作为薄组合根。

**Blocked by:** 02 / 实现确定性游戏规则引擎

**Status:** ready-for-agent

## Scope

- 新增 `src/renderer.js`，负责 devicePixelRatio 感知的 Canvas 尺寸、棋盘背景、蛇身、蛇头与食物绘制。
- Renderer 只消费规则引擎状态，不实现移动、碰撞、计分或方向判断。
- 新增 `src/runtime.js`，通过可注入 scheduler 管理唯一的固定 tick 循环，并发布最新状态供 UI 同步。
- Runtime 支持开始、暂停、继续、重新开始与销毁；暂停和 game-over 后不得遗留活动计时器，重复继续不得创建多个循环。
- 更新 `src/main.js` 连接规则引擎、Renderer、Runtime 和 01 已建立的 DOM hooks，但暂不实现最终键盘/触控输入适配和最高分持久化。
- 新增 `tests/runtime.test.js`，使用 fake scheduler 验证生命周期，不进行真实等待。

## Acceptance Criteria

- [ ] 静态页面可完成开始、按固定 tick 移动、进食后画面与当前分数同步、暂停/继续、撞击后停止的基础闭环；Runtime 测试证明任意时刻至多一个活动循环且暂停、结束、重开和销毁正确清理调度，既有规则测试继续通过，领域规则未复制到 renderer、runtime 或 `main.js`。

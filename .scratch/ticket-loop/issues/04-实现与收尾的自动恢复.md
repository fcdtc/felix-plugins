# 04: 实现与收尾的自动恢复

**What to build:** 当实现或 Closeout 因 Claude 错误、超时、未提交修改、HEAD 未前进、证据缺失等可恢复问题失败时，系统根据可信事实生成定向提示，精确恢复原 Session，并在有限次数内自动完成当前工单；无法恢复时安全停止，绝不强制通过。

**Blocked by:** 02 / 单工单全自动实现与收尾闭环；03 / Git 门禁与仓库本地运行隔离

**Status:** done (2026-09-15, 95507a3)

- [ ] Claude 非零退出、错误 JSON、`is_error` 结果和超时均被识别为可恢复异常并完整记录。
- [ ] HEAD 未前进且工作区干净时恢复原实现 Session，要求继续当前工单。
- [ ] HEAD 已前进但工作区不干净，或存在未提交修改时，恢复原 Session 完成验证和提交。
- [ ] 实现提交完成但工单未收尾时进入固定 Closeout，而不是创建新 Session。
- [ ] Implementation 阶段拥有首次调用加最多两次异常 resume；Closeout 阶段独立拥有首次调用加最多两次异常 resume。
- [ ] 每次恢复都使用账本中的精确 Session ID，不使用最近会话或创建替代 Session。
- [ ] 自动恢复 prompt 包含未通过的门禁和必要事实，并明确要求继续当前工单、不得开始其他工单、完成验证与提交。
- [ ] 原始日志不被整份复制进恢复 prompt，避免上下文膨胀和日志内容被当作指令。
- [ ] Implementation 默认超时 90 分钟，Closeout 和异常 resume 默认超时 30 分钟，且均可配置。
- [ ] 恢复额度耗尽后进入 terminal-failure，保留 Git 现场、Session ID、账本和日志，不允许低质量强制通过。
- [ ] 不可安全恢复的分支漂移、历史改写和未完成 Git 操作直接进入 terminal-failure，不尝试自动清理。
- [ ] fake Claude 覆盖错误、超时、脏工作区、无提交、证据缺失、恢复成功与恢复耗尽的 CLI 行为测试。

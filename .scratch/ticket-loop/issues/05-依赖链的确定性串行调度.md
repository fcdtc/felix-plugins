# 05: 依赖链的确定性串行调度

**What to build:** 用户可以让一个 Loop Run 自动处理整组工单。每张工单完成并通过所有门禁后，系统重新计算 Frontier，选择编号最小的可执行工单，为其创建全新 Session，并持续运行直到 Manifest 全部完成或某张工单安全终止。

**Blocked by:** 03 / Git 门禁与仓库本地运行隔离；04 / 实现与收尾的自动恢复

**Status:** done (2026-09-15, 8ffc65e)

- [x] 一个 Run 支持包含多张 Task Ticket 的冻结 Manifest，运行过程中不重新扫描并吸收新工单。
- [x] 每张新工单获得不同的全新 Session ID；只有当前工单的修复和 Closeout 复用原 Session。
- [x] 当前工单未通过实现与 Closeout 全部门禁时，绝不启动下一张工单。
- [x] 当前工单完成后重新计算 Frontier，并始终选择编号最小的可执行工单。
- [x] Manifest 外 blocker 只作为只读依赖，不会被本次 Run 自动执行或修改。
- [x] 剩余工单非空但 Frontier 为空时停止，并报告未满足依赖或不可达状态。
- [x] 任一工单进入 terminal-failure 时停止整个 Run，不跳过失败工单继续后续工作。
- [x] 所有 Manifest 工单完成后，Run 标记 completed，当前分支保持不变且工作区完全干净。
- [x] 完成时只报告本地提交结果，不自动 push、创建 PR 或清理 Session。
- [x] CLI 行为测试覆盖线性链、分叉 DAG、多个 Frontier、外部 blocker、中途新增文件、当前票失败和整链成功。

# 06: 可中断、可重开的持久运行

**What to build:** 用户可以安全中断、查看、停止和重新打开长时间运行的 Loop。系统在正常信号、进程崩溃和陈旧锁场景下保留足够状态，并只在仓库、Git 历史、活动工单和原 Session 均能验证时继续。

**Blocked by:** 04 / 实现与收尾的自动恢复；05 / 依赖链的确定性串行调度

**Status:** ready-for-agent

- [ ] Run Ledger 使用原子写入，记录 Manifest、阶段状态、Session ID、Git SHA、尝试次数、退出码、费用和日志路径。
- [ ] SIGINT 或 SIGTERM 到达时先向当前 Claude 子进程发送终止信号，宽限期后再强制结束，并记录 interrupted、释放锁、保留现场。
- [ ] Python 进程异常退出后，下次调用能通过陈旧锁和 running 状态识别 interrupted Run。
- [ ] 同一工单目录只有一个未完成 Run 时，普通入口可以自动恢复它。
- [ ] 存在多个未完成 Run 时 fail closed，并提供精确 Run ID 的恢复方式。
- [ ] `status` 只读返回运行阶段、活动工单、门禁、尝试次数和允许动作，不触发 Claude 调用。
- [ ] `abort` 只停止调度、更新账本并释放锁，不 reset、stash、删除 Session 或修改业务文件。
- [ ] 普通 `resume` 不能越过 terminal-failure。
- [ ] `reopen` 在恢复前重新验证仓库、分支、历史祖先关系、未完成 Git 操作、活动工单现场归属和原 Session 存在性。
- [ ] 原 Session 不存在时拒绝创建新 Session 接管半成品。
- [ ] `clean` 只在显式调用时删除指定 Run 的账本和日志；成功运行不会自动清理。
- [ ] CLI 行为测试覆盖受控中断、崩溃后陈旧锁、唯一/多个未完成 Run、abort、resume、reopen 和 clean。

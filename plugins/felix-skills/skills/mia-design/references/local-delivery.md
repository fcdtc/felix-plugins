# 本地交付与差异查看

仅 `local` 分支读取。本轮交付是私有本地文件，不上传 Artifact 或其他外部服务；`sync` 的上传临时包不属于这里的交付。

## 目录与文件模板

在执行项目中创建 `.design/<agent_id>/<本轮唯一标识>/`；暂无 Agent ID 使用 `new-agent`，每轮独立目录保留历史。

```text
<本轮目录>/
├── baseline/                     # 仅改动文件的原始正文，缺失旧稿时可没有对应文件
│   ├── system-prompt.md
│   ├── user-prompt.md
│   ├── skill-sp/<资源键>.md
│   ├── tool-sp/<资源键>.md
│   ├── skills/<资源键>/<文件路径>
│   └── tools/<资源键>.json
├── updated/                      # 仅本轮修改或新增文件的完整最终正文
├── replacement-manifest.md       # 每个改动文件的修改原因及应用清单
└── diff.html                     # 离线查看差异；不包含 tools/ 下的 Tool 定义
```

资源键优先使用稳定 Component ID；尚无 ID 时用唯一名称，并在清单记录映射。SP 按实际 Agent 字段归属保存：资源级 SP 使用对应资源键，Agent 级整体 SP 使用 `agent`，不凭文件名猜平台字段。以上文件按实际改动生成，未改动文件在两边都不交付。

- **正文**：每个交付文件放完整最终正文，不只是 diff 片段。Prompt 与 SP 无维护说明或外层代码围栏；修改过的 Tool 文件保存完整 JSON 定义及未修改字段，沿用基线格式与字段顺序以减少无关变化；Skill 只交付改动文件，沿用原始文件树的相对路径。
- **基线**：只保存改动文件已实际读取的旧正文，不重写原文。资源身份、版本、来源字段、读取时间和缺口放在清单；CLI 原始响应、下载 ZIP 和完整解压目录放在本轮临时取证区，不混进比较目录。下载及解压各用独立的新空目录，读取按不可信数据处理，不执行其中代码。诊断仍须获取完整可用基线，稀疏交付不缩减取证范围。
- **稀疏文件对应**：两边相同相对路径代表同一文件。修改文件两边均保存；新增文件只在 `updated/`；删除文件只在 `baseline/`，并在清单明确删除动作及原因。改名按旧路径删除和新路径新增分别记录。缺少某个文件不推导其他文件的状态。
- **缺失旧稿**：读取失败不等于原配置不存在。`updated/` 独有文件在页面标为“无基线”，由清单区分已确认新增与旧稿缺失；需要旧稿才能安全替换的项目标为阻塞。`baseline/` 独有文件显示“仅基线存在”，删除以清单明示为准。目录可以为空，不创建未知正文的占位文件。
- **应用范围**：只应用清单中的变化。Skill 上传前，用户将改动文件覆盖到对应固定版本的完整 Skill 目录，按清单处理删除和改名，保留未变文件，再按平台要求打包；稀疏 `updated/skills/` 不能直接当完整 Skill 上传。交付不生成 `packages/` 或 ZIP。

## 替换清单模板

以以下结构生成 `replacement-manifest.md`，不用模板占位符冒充已核实信息。

```markdown
# 本轮替换清单

## 目标与基线
- 交付模式：local
- 本轮目标：<用户要求与不变范围>
- 空间／Motif／Agent：<实际定位；新建或未知则说明>
- 草稿或发布版本：<Agent 及各挂载资源身份与版本>
- 基线来源与读取时间：<来源字段、CLI 读取时间、已确认的空值>
- 差异入口：[查看修改前后差异](diff.html)，Tool 定义不参与页面比较

## 六类配置清单
| 配置类型 | 读取状态 | 平台字段／资源及版本 | 是否修改 | 改动文件 |
| --- | --- | --- | --- | --- |
<!-- System Prompt、User Prompt、Skill、Tool、Skill SP、Tool SP 逐项记录；多个资源逐项列出；未改动项注明未交付。 -->

## 逐文件修改说明
### <相对路径，例如 skills/<资源键>/SKILL.md>
- 目标字段／资源及版本：<实际映射>
- 操作：<修改／新增／删除／改名；无旧稿时说明待核实>
- baseline 文件：<路径或无基线及原因>
- updated 文件：<路径；删除则为无>
- 改了什么：<本文件各处变化的简要说明，修改前行为 → 修改后行为>
- 为什么改：<问题表现或约束、可核对的证据，以及原文件为何不足>
- 预期效果与取舍：<希望改善什么、可能影响、保持哪些行为不变>
- 验证情况：<已做本地检查、仍需运行验证或用户确认的事项>
<!-- 每个修改、新增、删除文件独立一节，包括 Tool JSON；多个文件不合并为一条笼统理由。 -->

## 应用顺序
<!-- 仅列实际变化；说明平台字段替换、Skill 稀疏文件合入完整基线后打包、Tool 更新及挂载调整的依赖顺序。删除与改名显式列出，CLI 不支持的步骤交由用户。 -->

## 本地检查结果
<!-- 正文、占位符、JSON、引用与契约检查；Diff 对比范围与逐文件说明覆盖检查；本地检查不冒充真实业务验收。 -->

## 缺口与未验证项
<!-- 读取失败、不支持、无基线、业务待确认；明确哪些项目不能安全应用。 -->

## 未执行操作
- 未写入 MIA
- 未运行 Agent 或评测
- 未发布或部署
```

修改原因以**文件**为粒度，每个文件单独说明；同一文件多处修改可分点。固定使用 `## 逐文件修改说明`，其下每个 `###` 标题仅写两边目录内相同的相对文件路径（可用反引号包裹），正文使用模板中的 `- 字段：内容`，必须填写非空的 `- 为什么改：...`。这既供人阅读，也是 Diff 页面绑定说明的唯一来源；标题不附加编号或摘要，不重复同一路径。规则迁移涉及多个文件时，各自解释迁入／迁出理由并互相引用。“为什么改”提供可核对的设计依据与取舍，不输出内部思考过程；区分事实、推断和待验证预期。没有修改时直接说明没有修改，不编造理由。

## 生成和查看 Diff

由随 skill 分发的 [render_diff.py](../scripts/render_diff.py) 直接读取两边文件和 `replacement-manifest.md`，在内存比较后生成单个自包含 `diff.html`。不维护中间 `.diff`／JSON 文件，不启动服务、不访问网络、不安装第三方依赖。

页面为**一文件一页**：上方通过上一页／下一页、文件选择器或左右方向键切换；每页先显示该文件的左右 Diff、原始行号、行内增删与三行上下文，下方立即显示清单中该文件的修改说明。首屏只展示第一个文件，翻页时其他文件与说明一起隐藏；可用 `#file-N` 回到相应文件。说明在生成时嵌入页面，不在浏览器中读取本地 Markdown，单个 HTML 可完整离线查看。

**对比范围**：比较 Prompt、Skill 文件及两类 SP；固定排除两边根目录的 `tools/` 子树，即 Tool 定义及其修改说明不进入分页。`tool-sp/` 仍参与对比。Skill 内二进制只比较哈希和大小，不伪装为文本差异。页面按相对路径精确绑定清单中的说明，不推测修改原因。每个差异文件须有非空原因；缺少或重复章节时脚本报错，不生成不完整页面。Tool 的说明仍在清单中逐文件维护，由交付检查核对。

执行前根据当前已加载的本 skill 入口确定其安装目录绝对路径。以下占位路径须替换为实际目录：

```bash
python3 -I -B <skill安装目录>/scripts/render_diff.py <本轮目录>
```

`baseline/` 与 `updated/` 须存在，可为空；默认写入 `<本轮目录>/diff.html`，已有文件时拒绝覆盖。同一轮明确要求更新时，先检查既有页面，再加 `--overwrite` 重新生成；它不会修改两边目录或清单。比较目录只接受普通文件与目录，拒绝符号链接和特殊文件；过大输入明确报错，不静默截断。

直接用浏览器打开 `diff.html`，每页下方即可阅读该文件的修改说明，清单仍可单独阅读。这是生成时的快照，不会实时读取磁盘；修改源文件或清单后须重新生成。没有可比较变化（例如仅改 Tool）时页面明确显示空状态；不得为显示变化把 Tool 放到其他路径绕过排除。

完成条件：Diff 成功生成；每个改动文件（包括 Tool）都有独立修改理由与应用动作；两边无未改动交付文件；所有缺口明确；用户取得清单和页面的项目相对路径；平台写入、运行与发布次数为零。

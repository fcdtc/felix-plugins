# Init 流程（无 `.learn/` 时执行）

目标：在目标代码库根目录建立 `.learn/` workspace，产出**代码地图**、**课程大纲**和第一课 `index.html`。init 完成的判据：三个文件都已写入，且第一课在浏览器直接打开可用（含步进器与预测题）。

## 1. 扫描代码库，建代码地图

读 README、包管理配置、入口点、目录结构，追踪主要 import/调用关系，自己弄清这个库是干嘛的——不问用户。

将**代码地图**写入 `.learn/code-map.md`，包含：

- **一句话定位**：这个库是什么、给谁用
- **模块清单**：每个模块一行 —— 路径、职责（一句话）、关键文件、对外接口要点
- **入口点**：CLI 命令 / HTTP 路由 / 事件订阅 / main 函数，各自落到哪个文件
- **依赖关系**：模块间谁调用谁（邻接表即可，不用画图）
- **一条典型链路**：挑最核心的一条请求/命令/数据流，从入口到出口列出经过的文件与函数（这是第一课动画的素材）

地图是给后续每课用的索引，不是文档：每个模块 2–4 行足矣，宁可粗而全，不要细而漏。

## 2. 生成课程大纲

写入 `.learn/outline.md`：

- 第一课固定为总览课（见下）
- 之后按模块排出课时序列（架构总览 → 核心链路 → 各模块），每课一行：编号、标题、预计覆盖的模块/链路
- 大纲是骨架，不是承诺：标注「深度按 learning-records 动态调整」

## 3. 生成第一课 `index.html`（总览课 = 课程首页）

第一课的使命：让用户对整个项目**建立整体心智模型**。五个必备 section，缺一不算完成：

1. **整体认识**：一句话定位 + 这个库解决什么问题（为什么值得学）+ 核心功能盘点
2. **清晰的架构图**：用 `.tutor-arch` 分层架构组件（层 = 职责层，节点 = 模块，依赖方向向下；入口/边界模块用 `.entry` 高亮），配两三句「为什么这样分层」的设计取舍
3. **代码目录结构**：`.dir-tree` 目录树，每个关键目录后跟一行注释说明职责（只列关键目录，不穷举）
4. **数据流流向**：用 `.tutor-flow` 数据流组件，把代码地图里的典型链路做成逐步点亮动画，讲清一条请求/命令从入口到出口经过了谁；可配一个执行步进器展示链路上最关键函数的运行时行为
5. **课程安排**：`outline.md` 的课程表 —— 每课标题 + 一句话内容 + 状态（已开课 `<a>` 链接 / 未开课 `<span>` 标记），用户由此知道接下来学什么、点进去能继续

页脚放「下一课 →」链接，指向大纲第二课的规划文件名（未生成也照链，规则见 `references/lesson.md` 的「页脚三向导航」）。

结尾必须有一道**预测题**（三选一，考「这条链路里谁负责 X」级别的全局理解）。

课程 HTML 骨架与组件接线照抄 `references/lesson-template.html`。

## 4. 状态文件

写入 `.learn/state.json`：

```json
{
  "repo": "/absolute/path/to/repo",
  "created": "2026-08-22",
  "lessons": ["index.html"]
}
```

（时间用 `date +%F` 实际获取。）

完成后告知用户：workspace 位置、如何继续学习（再次调用 `/codebase-tutor` 即生成下一课）、`.learn/` 默认不入 git、想共享时 `git add -f .learn`。

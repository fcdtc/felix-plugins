# 单课生成流程（有 `.learn/` 时执行）

目标：生成下一课 `lessons/NN-slug.html`，10–15 分钟一个完整可讲述单元。完成的判据：HTML 写入、`state.json` 更新、learning-record 写入、课程含至少一个执行步进器和一道预测题、浏览器直接打开可用。

## 1. 选题（ZPD）

按顺序确定本课主题：

1. 用户当场指定了主题 → 用它
2. 否则查 `learning-records/` 里的**未解之谜**（未闭环的 mystery 优先 —— 它们是用户自己提出的问题）
3. 否则按 `outline.md` 顺序取下一个未讲课时

选题后**现读相关代码**补充细节：代码地图只是索引，本课涉及的文件必须打开读过，代码片段必须是从真实文件复制的（带文件路径），不许凭地图想象。

深度按 learning-records 调整：用户已掌握的概念一笔带过甚至不提；记录中出现过误判的概念，正面澄清。

## 2. 版本检测

开课先检测本课要用的文件相对上一次记录的 commit 是否变化：

```bash
git diff --quiet <hash> -- <file...> || echo CHANGED
```

（无 git 或无历史时跳过。）若变化：告知用户「本课将基于当前代码生成」，并按当前代码写课。对**已生成**的旧课程不做任何自动更新。

## 3. 写课

- 结构与组件接线照抄 `references/lesson-template.html`，`assets/` 已在 workspace，课程 HTML 里只填数据与讲解文字
- **每课必须包含**：≥1 个执行步进器（真实代码逐行 + 变量同步）、1 道三选一预测题（唯一强制练习，放在结尾）
- 数据流动画、代码↔英文对照按内容需要选用
- 中文授课；代码、函数名、术语保留英文
- 只讲代码现状，不涉及 git 历史

**内容高度（重要）**：讲作者的设计思路与整体架构，不做逐行代码解析。代码的角色：

- 真实代码片段只用来**定位**（"就是这几个文件里的这几个函数"）和喂给执行步进器
- 设计亮点与巧思用**简化伪代码**呈现 —— 抽掉错误处理、边界情况等噪音，只留表达思想的骨架：

```
// 讲"洋葱模型"的巧思时，写这个就够了：
middleware = stack of functions
request 穿过 stack（正向依次执行）
response 沿原路返回（反向依次执行）
```

- 判断一节课好坏的标准：学完后能否**向别人转述这个库的设计取舍**（为什么这样分层、为什么选这个模式、换种做法会牺牲什么），而非能否背诵实现
- HTML 顶部写 tutor frontmatter（HTML 注释，格式见 lesson-template.html）：本课依据的文件清单 + 生成时的 commit hash（`git rev-parse HEAD`）
- **页脚三向导航**（首页 · 上一课 · 下一课）：下一课链接**永远预先建好** —— 按 `outline.md` 规划的下一课文件名写死（如 `lessons/03-router.html`），即使该课尚未生成也照链（点开是空白页），课程生成到该文件名后链接自动生效，无需回改旧课。本课若已是大纲最后一课，下一课链接指向 `#` 并标注「待规划」。文件名一旦用于链接即固定：后续生成该课时必须用同名文件

预测题的出题原则（对抗 Fluency 错觉）：答案是「读了本课后稍加推理才能得出」的，不是课文原句复述。错误选项要用用户**容易误判的方式**构造（参考 learning-records 里的历史误判）。

## 4. 更新状态

- `state.json` 的 `lessons` 数组追加本课文件名
- 若本课对应 `outline.md` 某课时 / 解开某个未解之谜：更新 `index.html` 课程安排表中对应项（`<span>` 未开课 → `<a>` 链接）
- 写一条 learning-record（格式见 `references/learning-records.md`）：本课讲了什么、用户的困惑或误判（若有）、产生的新未解之谜（课堂上用户提出的、未展开的问题）、闭环的旧 mystery 标记 `Status: resolved`
- 用户没说话时，从课堂交互中能沉淀的就只有课程内容本身 —— 照实记录，不编造用户反应

## 特殊操作（参数触发）

- `regenerate NN`：按当前代码重写 `lessons/NN-slug.html`，frontmatter 换新 commit，内容主题不变
- 用户指定主题：同上流程，选题跳到第 1 条

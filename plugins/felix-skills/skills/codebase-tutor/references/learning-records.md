# Learning Records 格式

存放于 `.learn/learning-records/`，首次写入时创建目录。编号递增：`0001-slug.md`、`0002-slug.md`。

它是教学版的 ADR：沉淀**会改变后续教学决策**的信息 —— 已学过什么、用户在哪里困惑过、误判过什么、还有什么没解开。这些记录是 ZPD 判断的依据：下一课的深度和切入点由此决定。

每课生成后写一条；用户表达困惑/纠正认知时也可随时补写。**照实记录，不编造用户反应。**

## 模板

```md
# NNNN. 标题（本课主题或事件）

Date: YYYY-MM-DD
Lesson: lessons/NN-slug.html（如非课堂产生可省略）

## 内容

本课讲了什么：覆盖的模块/链路、核心结论。3–5 行。

## 已掌握

- 本课明确建立的概念（后续课程可直接使用，不必重讲）

## 困惑与误判（如有）

- 「曾以为 X 负责路由，实际是 Y」—— 具体到用户的原话或复述
- 错误选项里埋过的坑（用户答错过预测题的话）

## 未解之谜（如有）

- [ ] 用户提出但未展开的问题，一两句话记下 —— 后续课程的候选素材
- [x] 已解开的问题，注明在第几课闭环

## Status

active（含未闭环 mystery） / resolved（本记录的谜题已全部闭环）
```

## 规则

- 一条记录一个主题；闭环旧谜题改原记录的 checkbox 与 Status，不新开重复记录
- 「已掌握」条目要具体到概念粒度（「Koa 中间件洋葱模型」），不要写「了解了路由」
- 未解之谜是第一优先级的选题来源：用户自己提的问题，讲它命中 ZPD

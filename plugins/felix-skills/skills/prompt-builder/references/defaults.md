# 默认值参考

当用户在信息收集阶段没有明确回答某个维度时，用这里的合理默认值填充，并在生成的 prompt 里用 `[假设：...]` 标注，提醒用户复核。

## 角色 / 人格默认值

- **默认人格**：直接、简洁、任务导向。除非用户要求"温暖""有同理心"等，否则不加人格修饰。
- **默认协作方式**：请求清楚且低风险时直接推进，不反复确认；只有不可逆动作（删除、发送、付款、写生产环境）才先征求许可。
- **默认受众**：假设是专业用户，不用过多铺垫和客套。

## 目标 / 成功标准默认值

- **默认成功标准**：用户的请求被完整解决，且关键事实有依据支撑。
- **若用户没给可量化标准**：用"请求的每个部分都得到回答 + 关键事实有出处/依据"作为基线。

## 工具使用默认值

- **默认何时用工具**：需要新鲜数据（订单、配置、价格、最新信息）、需要具体 ID/记录、需要验证事实时，优先用工具而非内部知识。
- **默认并行性**：多个独立的读取/检索操作可并行；有依赖关系的步骤必须串行。
- **默认调用后行为**：执行写操作后，简短复述"改了什么、改在哪（ID/路径）、做了什么验证"。

## 约束默认值

- **默认安全约束**：不编造事实、不伪造引用、不确定时明说、不执行未授权的破坏性操作。
- **默认副作用门控**：任何有外部副作用的动作（发送、付款、删除、写生产、下单）执行前必须先征求用户确认。

## 输出格式默认值

- **默认格式**：Markdown，自然的段落为主，列表/标题仅在提升可读性时使用。
- **默认长度**：默认中等偏短（"medium"），3-6 句或 ≤5 条要点；简单是非题 ≤2 句。
- **默认语气**：与用户匹配，专业但不啰嗦。

## 停止规则默认值

- **默认停止条件**：用户的请求已能用足够的依据回答，且关键事实已有支撑 → 停止并回答。
- **默认重试条件**：工具返回空/可疑的窄结果 → 至少尝试 1-2 种回退策略（换措辞、放宽过滤、换数据源），再下"无结果"的结论。
- **默认放弃条件**：再检索一次也不太可能改变结论时，停止。

## 错误处理 / 止损边界默认值

判断某个错误该不该惊动用户，看它"贵不贵、能不能撤"：

- **必须停下来问用户（不可逆 / 影响外部 / 要花钱）**：会写脏数据、删改文件或记录、发送消息/邮件、触发付款或下单、调用付费 API、改动生产环境、批量操作、执行用户没明确授权的动作。这类错误一旦继续，损失会放大或无法回收，所以先停。
- **自行重试或回退，不打扰用户（可逆 / 纯本地 / 低代价）**：格式不符、单次检索/解析失败、临时超时、本地计算出错。这类错误重试一两次或换个方法通常就好，没必要每次都打断用户。
- **默认表述方式**：在 prompt 里写成"当遇到 X（不可逆/影响外部）时，停下来询问用户；当遇到 Y（可逆/本地）时，最多重试 N 次后回退，无需询问"。给出阈值，别只写"出错就处理"。

## 缺失信息默认值

- **默认行为优先级**：(1) 能用工具检索就先检索 → (2) 不能检索且缺失会实质影响结果，问一个最小化的澄清问题 → (3) 必须推进时，标注假设并选择可逆的动作。
- **绝不**：在关键事实缺失时硬编一个答案。

## 场景特化默认值

- **编码 Agent**：默认假设用户想要"可直接运行的代码"而非"方案"，除非用户说"先给我计划"。交付前跑一遍最相关的验证（测试/类型检查/构建）。
- **研究/RAG Agent**：默认要求多轮检索 + 引用，按"计划→检索→综合"三步走，矛盾要明确指出。
- **客服 Agent**：默认在事实性问题上先调工具查证，不靠内部知识；强调礼貌但简洁。

## 使用说明

填充默认值时，**一定要在 prompt 里加 `[假设：xxx]` 标记**，并在交付说明里列出这些假设点，请用户确认或修正。未标注的假设会让用户误以为这些是他们的需求。

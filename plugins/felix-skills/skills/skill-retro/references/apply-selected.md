# 实施已选建议

仅在用户明确选择已展示的建议编号或修改方面后读取。实施范围以用户的选择为准，未选建议保留在清单中。

## 1. 核对范围与编辑基线

把用户选择映射到候选编号、预期行为和拟改文件。部分选择不扩大成全部修改；含糊回复先澄清。确认后的范围内持续推进，进度汇报不是暂停点。

通过实际加载路径、符号链接和项目配置定位本地维护源；位置有歧义时请用户指定，不默默修改安装缓存或生成副本。读取修改前内容与现有差异，保留用户尚未提交的工作。磁盘已有后续变更时，重新判断选定问题是否仍存在，已修复项说明无需再改。

选定建议需要额外的独立改动，或会改变职责、业务边界时，先展示新增影响并取得用户选择；可独立完成的已选项继续推进。范围外技能、全局规则、运行时权限和业务代码仍仅给建议。

完成条件：选定项、必要支持文件与维护源已定位，当前编辑基线已核对；阻塞项和无需再改项已分开。

## 2. 最小修改

编写前读取 [writing-for-agents](../../mattpocock/productivity/writing-for-agents/SKILL.md)；涉及 frontmatter、调用策略或拆分技能时，再读取其 [Skill mechanics](../../mattpocock/productivity/writing-for-agents/SKILL-MECHANICS.md)。

在目标既有结构内落实已选建议，保留正常分支、原有职责和调用策略。需要确定性检查时优先复用已有脚本；确有缺口才在目标 Skill 范围内补小型检查及测试。

修改范围为目标 Skill 及落实已选建议所必需的引用、脚本和平台支持文件。按目标仓库约定同步注册、依赖、平台 sidecar 与发布版本；注册已经覆盖时不重复添加。

完成条件：实际 diff 中每处行为变更都能追溯到已选建议及本次证据，没有夹带无关清理或个人数据。

## 3. 验证

检查 diff、引用、frontmatter、调用策略一致性，运行目标仓库要求的校验；涉及脚本时运行对应测试。不要用清理用户改动的方式获得干净基线。

对每项实际修改做两次静态走查：

1. **原问题**：代入本次输入，指出新规则在哪一步改变原来的错误动作或表达。
2. **相邻场景**：换一个正常输入或边界条件，检查正常流程仍能完成，规则没有只适配本次案例。

静态走查不是实际执行验证。默认不重新调用目标 Skill，不启动批量评测或后台复盘。用户要求实跑时，先核对运行授权、费用和副作用，优先使用隔离副本或只读用例；修改后的规则必须在测试上下文中重新加载。重复写入、发送、发布等外部动作另行确认。缺少运行条件时交付可执行的复测输入和通过标准，明确未实跑，不宣称效果已证实。

完成条件：必要检查已有实际结果；静态走查与实跑验证分开，未验证项及原因明确。

## 4. 交付结果

简洁列出：

- **已选项与改动**：逐项说明已修改、因已修复而无需修改，或受阻；附可点击文件位置。
- **验证**：实际检查及结果、两类静态走查结论；未实跑项单列。
- **保留项**：未选建议保持未修改，后续需要用户选择的事项另列。

完成条件：选定改动与校验已完成，或明确说明阻塞项及所需输入；如实区分已修改、已静态检查和已实跑验证。

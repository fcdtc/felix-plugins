# MIA Agent 链路设计与优化

从业务职责和证据出发优化整条链路，不把所有问题都变成 System Prompt 的补丁。设计方法与平台操作分开：涉及线上查询、保存、挂载或运行时，先加载当前环境的 `miacli` 及对应子流程，命令和平台能力以其说明、帮助及实际返回为准。若环境没有该依赖，继续本地设计，明确线上步骤缺少的能力，不拼私有 HTTP 绕过。

## 1. 确定本轮目标

从用户请求确定：新建还是优化、目标场景、问题表现、交付范围，以及允许本地修改、草稿同步、运行或发布到哪一步。复用已给定位和授权；只询问影响下一步的业务决策，不让用户查可自行读取的事实。

先约定本轮验收到哪层：

1. 配置一致：Prompt、Skill 文件与引用、Tool 挂载正确。
2. 流程正确：路由、分支、工具调用和边界正确。
3. 参数合理：请求有依据，满足领域规则和 Schema。
4. 业务有效：真实生成、保存或其他业务结果达到要求。

用户只要求调用覆盖时，不擅自扩展为真实业务验收；用户只要求本地文件时，不访问或同步平台。设计确认不是发布授权，历史项目授权不自动扩展到新资源。

完成条件：目标、允许动作、验收层次、已知问题与不变范围明确。

## 2. 建立基线并定位问题层

读取项目规范和已有设计；若需平台操作，按 miacli 回读目标完整配置、草稿／发布态、挂载资源与实际契约。新建场景先盘点可复用能力，不默认新建一套工具。

记录：输入、System/User Prompt、Skill 正文和文件树、Tool Schema与返回、模型与调用预算。区分文档设计、已挂载声明、真实调用结果。资源身份、版本和调用证据写入本轮记录，不写进通用 Skill。

用 [问题定位与验收](references/validation.md) 将症状归到事实、编排、决策、接口或运行层。只改受影响的层，保留其他配置；工具缺能力不能靠 Prompt 编出能力。

完成条件：现状、缺口和本次修改层有事实依据；无基线的部分明确标为未知。

## 3. 划分场景和信息归属

先列出每个场景的触发、工作对象、职责、允许动作、禁止动作与完成条件。多分支场景逐项判断，分支静默或受阻不能自动结束整轮；不要求每项职责都产生写入。

按 [五层分工与模板](references/layers.md) 分配内容：

- 工程 RPC：身份、场景、引用和触发事实。
- MIA 入参：本轮对象、背景、观察窗口、准备情况与缺失。
- System：固定场景路由、共同边界、Skill 编排与整轮完成条件；User：placeholder 呈现本轮材料。
- Skill：业务判断步骤、证据要求、工具选择与分支完成条件。
- Tool：能力、可执行参数、返回及错误语义。

handoff 类字段是本次导读，不复制完整 SOP；关联上下文保留对象事实，不与导读各维护一份真值。既有入参若已固定，不为采用模板擅自新增字段。

新增场景只补必要入口与流程；有独立可复用职责才拆 Skill，不按场景数量机械复制。业务边界需要用户把关时，先提出具体案例和推荐，再等待决定；其余事实调查和独立准备继续推进。

完成条件：每条规则有明确的权威来源，每个场景都有入口和退出条件，关键业务边界没有被实现细节暗中决定。

## 4. 编写可执行的 Prompt 与 Skill

调用同插件的 `writing-for-agents`，按其信息层级、触发指针和完成条件组织文档。

- System 明确场景入口及所需 Skill；多分支先形成候选，再协调重复、负荷与依赖，最后提交动作。Skill 完成不等于整轮完成。
- User 模板与实际 MIA 入参同名绑定；保持一处动态事实来源，不另写冲突的职责规则。
- Skill 写清何时查询、何时可复用、什么事实足够行动、缺什么停止。保留业务语义，不嵌入调度、部署、模拟实现状态或临时版本兼容。
- 字段格式与能力映射应由真实 Tool 契约和领域指南支持，不凭名称猜测。实现替换而业务契约不变时，Skill 应可复用；契约本身改变仍须对齐。
- 对一次工具调用决定产出质量的能力，读取 [能力目录与参数决策指南](references/capability-guides.md)，按需建立负责人维护的 reference，不把全部指南塞进固定提示词。

平台不支持按场景工具权限限制时，不把该功能当作前提；说明行为规则不等于硬拦截，并用越界案例检查。

完成条件：能从输入沿流程走到真实动作或明确的不行动结论；Prompt、Skill 和 Tool 无互相冲突的指令，待补规范不伪装为已确定规则。

## 5. 本地检查与授权范围内同步

先交付并检查必要文件：入参书写规范（含场景样例）、System Prompt、User Prompt、Skill及按需参考指南。规模小的修改只改已有对应文件，不为凑交付物新增文档。

检查 placeholder、JSON二次解析、引用路径、能力枚举、必需数据来源、文件树与完成条件。同步前再次读取目标，合并当前配置；保留非目标字段和别人修改，使用最新乐观锁。冲突时重新合并，不只是换锁重放。

完整打包 Skill，含仍需保留的 references 等文件；保存后回读正文与完整文件树，再刷新 Agent 对该 Skill 的引用。Prompt 同步只取正文，不上传文档状态和维护说明；重复或冲突的附加提示一并核对。

写操作结果未知先查询原资源，不重复创建。具体 CLI 操作和资源版本语义遵循 miacli，不在本文缓存命令、版本号或内部接口。

完成条件：本地检查通过；若同步已授权，保存与回读逐项一致，未授权变化为零。仅本地交付时到此停止，不默认运行模型。

## 6. 固定案例验证并闭环

运行前按本轮验收层次和授权选择固定案例，读取 [问题定位与验收](references/validation.md)。验证真实输入、实际加载的 Skill/reference、Tool 参数与返回、最终结论；不只看回答文字。

失败定位到最早受影响层再修正。保留原失败和版本，修复后新一轮证据不能抹掉历史；未知写入先核验，不能机械重跑。效果未达标时，不把 Mock、上传成功或 RUN_FINISHED 当作业务成功。

达到本轮目标后汇总修改、精确版本、验证层次、已知缺口和未执行项。发布仅在授权范围内进行，发布后回读固定依赖与已验收配置；草稿运行不代表正式版验证。

完成条件：每项验收结论有对应证据，未覆盖项明确，后续任务不冒充本轮已完成结果。

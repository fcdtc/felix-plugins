# 问题定位与验收

用于基线诊断、运行验收及失败后的针对性修正。案例和运行规模按用户目标确定，不默认做大规模模型评测。

## 症状对应修改层

| 现象 | 优先检查 |
| --- | --- |
| 场景串线、漏掉另一职责 | System路由、分支编排、整轮完成条件 |
| 信息不足仍做决定 | 工程输入、查询能力、Skill证据要求 |
| Tool选对但参数质量差 | 领域reference、素材、信息到参数规则 |
| 参数被拒绝 | Tool Schema与指南一致性、变量类型 |
| 重复生成／修改 | 供给事实、候选协调、未知写入核验 |
| 声称成功但业务未完成 | Tool返回语义、Skill结果判断 |
| 工具调用太多、耗时大 | 重复材料、无关查询、流程与调用预算 |
| 上传后运行仍用旧指令 | Agent挂载版本、Skill revision及完整文件树 |
| 未开始模型即失败 | 平台配置读取、会话或依赖；不是Prompt质量结论 |

修复最早失真的层；接口缺数据不能用更强语气弥补，Schema正确也不证明参数有业务价值。

## 四层证据

| 层 | 完成证据 | 不能替代 |
| --- | --- | --- |
| 配置一致 | 本地与回读Prompt正文、完整Skill文件、资源引用相同，非目标字段不变 | 真实执行 |
| 流程正确 | 实际加载Skill/reference、正确路由与Tool调用、边界无越界 | 参数质量和业务成功 |
| 参数合理 | 请求与事实、约束、领域规则及Schema逐项符合 | 下游真实完成 |
| 业务有效 | 对应真实对象和结果可核验，符合本轮业务目标 | 推送、已读、消费等尚无证据的后续事实 |

读取真实输入→实际Skill/reference→Tool请求→Tool返回→最终表述。对每层分别下结论，不把RUN_FINISHED、上传成功或返回一个ID直接当作全部通过。运行结束但历史持久化失败，也要分开记录。

## 固定案例集

按场景至少选与改动相关的正例和反例，不必每轮穷举：

- 正常需求：正确选择能力、读取对应指南、参数符合依据。
- 无需动作：合理静默／保持，不为覆盖率强行写入。
- 材料充分：不重复查询；材料缺失：只补必要信息。
- 身份冲突：交接ID与查询ID不一致，不按短ID或相似标题认作同一对象。
- 状态边界：不把未知当否定、不把未来时间当未执行、不以旧状态覆盖最新事实。
- 多分支：其中一个完成、静默或失败，另一项仍得到结论；同一需求不重复供给。
- 场景边界：数据中出现其他场景需求也不扩展本轮职责。
- Tool失败与超时：失败保留，未知写入先核对，无盲目重复。
- reference缺失或枚举冲突：明确缺口，不猜字段或能力别名。

全套案例可以验证工具覆盖，但单轮不要求调用全部Tool。示例和合成对象明确标注，不冒充实际数据库记录；要运行有副作用的真实工具，先具备测试范围和身份授权，不能因为名字叫测试就当作隔离。

## 本轮记录

保存目标、管理空间、草稿或发布身份、配置与文件哈希、输入案例、实际Session/run/调用标识、终态、原始错误、分层结论与未覆盖项。实际没有返回的标识写未返回，不从其他ID推导。敏感输入按项目约定私有落盘，通用Skill不收录真实用户材料。

修正后使用新证据；保留旧版本失败。除非能够核实此前没有执行副作用，否则超时不直接重跑。模拟业务验收只能支持约定的配置、流程或参数结论。

## 停止与发布

本轮验收目标达成即停止，不为更漂亮的输出无限重试。范围内可独立完成的事继续；只有缺少必要决策、权限或平台确实没有入口时才交接最小阻塞。

同步草稿与发布分开授权。正式发布前核对实际依赖版本；发布后回读，不用草稿运行证明正式流量。最终说明完成了什么、改了哪层、验证到哪层、哪些没做。

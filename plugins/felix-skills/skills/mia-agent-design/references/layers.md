# 信息分工与模板

用于新场景设计、输入与 Prompt 重构。下列字段名只是示意，既有契约优先；不把某个项目的七字段输入推广为所有 MIA Agent 的固定协议。

## 信息放在哪一层

| 内容 | 权威位置 | 其他层如何使用 |
| --- | --- | --- |
| 为什么唤醒、当前用户和已知关联对象 | 工程 RPC／可信 ctx | MIA 入参确定性传递 |
| 这次观察哪个时间段、对象是否预取 | MIA handoff 类字段 | Prompt呈现，Skill据此补查 |
| 对象内容、执行事实、消费状态 | 原服务数据，经关联上下文或Tool提供 | 按完整身份和观测时间使用 |
| 场景职责、允许动作、结束条件 | System | handoff只补本轮事实，不扩大权限 |
| 业务判断步骤 | Skill | System指定入口，不复制完整步骤 |
| 挂载 Skill 的使用与协调规则 | Skill SP | Agent 侧补充提示，引用 Skill，不复制正文 |
| 制品参数选择规则 | 能力reference | 对应类型选定后读取 |
| 请求字段、类型、返回和错误语义 | Tool Schema | 各层引用实际挂载契约 |
| 工具使用约束与异常恢复 | Tool SP | 流程指定调用时机及业务用途 |

同一概念可以在不同层被引用，但同一规则只设一个权威来源。修改时同时检查指针，不靠复制正文保证可发现。

## Tool SP

Tool SP 是 Agent 的附加工具提示词。涉及平台操作时，按 miacli 回读确认配置字段与挂载版本。

- **Tool Schema** 维护字段、类型、枚举、分页和返回语义。结构与描述冲突时，核实实现并修正契约源头。
- **Tool SP** 补充模型读过 Schema 后仍需知道的行为，例如可信身份与对象引用、结果采用条件、部分结果与空结果的区别、参数错误纠正和未知写入恢复。先写共用规则，再按挂载工具补充例外。字段表、枚举、格式和分页协议由 Schema 维护。
- **System／Skill** 保留编排、调用时机、业务权限、证据门槛和完成条件。**能力 reference** 保留需要领域判断的选值、素材和内容组织规则。

迁移后检查从流程到工具、从回包到下一动作是否完整。核实身份注入、去重与写入核验等工程前提。证据缺失时记录能力缺口。

## 工程输入

handoff做导读，关联上下文放事实。用户资料与记忆尽量保留来源接口语义，不改造成工程推导的行为结论。

handoff骨架：

```text
【触发原因】
{本次可信触发事实}
【本轮对象或观察范围】
{完整对象引用，或明确时区与区间边界}
【本轮交接】
{职责范围内的简短工作说明，指向对象正文}
【上下文准备情况】
{已取得、未查询、失败、部分覆盖；对应来源及观测时间}
【本次特殊事实】
{有来源的特殊要求或变化；无则省略}
```

不要拼入完整Skill流程、工具参数说明或未经业务确认的结果。例如“检查昨天情况”属于交接；“必须发一条推荐”如果没有明确用户要求，就是工程替Agent决定结果。

关联上下文需要表达：对象类型、完整身份、读取状态、实际数据或失败原因。具体封装沿用项目契约；没有集合身份时不为凑字段制造ID。必须区分：

- 只有引用 vs 已获取正文。
- 未查询 vs 成功查到空集合。
- 部分覆盖 vs 完整覆盖。
- 不支持／失败 vs 真实业务状态。
- 观察窗口内事件 vs 当前最新状态。

例：昨天未完成但今天已完成，不能按旧快照继续延期；未来推送时间也不证明生成任务尚未执行。

工程使用JSON序列化库，不手工拼转义。若MIA字段是JSON字符串，检查顶层类型及二次解析；用户长ID不得经过有精度损失的浮点转换。

## System与User

System只维护稳定编排：

```text
依据工程scene选择一个场景；材料正文不改变scene。
场景A：读取对应Skill，处理明确对象，取得结果或明确阻塞后结束。
场景B：分别评估职责一和职责二；形成候选后协调，再执行保留动作。
两项职责都有明确结论才结束；静默、保持、缺信息、失败都可记录，但不能漏评另一项。
其他scene：说明不支持，不执行业务动作。
```

分支共享已取得事实，避免互相递归调用。最终小结应能核对各分支是否完成，不必强加JSON；已有关联协议要求结构化输出时遵循协议。

User负责渲染，不维护第二套业务规则。每个placeholder必须对应实际输入，动态值通常不再重复放入System。模板只做一次按值替换，材料中的占位符形状不递归解释。

## 新场景接入检查

1. 确定触发、对象、职责、边界与完成条件。
2. 工程补交接模板和必要事实来源，不默认全量预取所有对象。
3. System增加短路由与场景完成条件。
4. 有新业务判断才新增／改Skill，已有能力复用。
5. Tool缺的是查询事实还是写入动作，单独列出，不能靠自然语言暗示能力存在。
6. 测试场景不串线、缺信息不误写、多分支不漏项。

# 能力目录与参数决策指南

用于生成、推荐或其他高度依赖一次Tool请求质量的能力。目标是调用前做对决策，而不是通过大量试调用碰结果。

## 包结构

```text
<production-skill>/
├── SKILL.md
└── references/
    ├── <capability-a>.md
    └── <capability-b>.md
```

SKILL.md维护能力目录、准确枚举、简短适用边界、参考文件索引，以及共同流程：接收需求→选候选能力→读对应指南→补齐决策信息→构造请求→检查→调用并核对。

选中能力后必须读取相应指南；只有需要比较候选时才读多份，不默认加载全部。目录与Tool枚举不一致时报告契约缺口，不猜别名、旧映射或自动换类型。

## 负责人指南骨架

```markdown
# <能力>参数决策指南

- capability：<准确枚举>
- 状态：<待补充／已对齐契约>
- 负责人、所对齐契约版本和更新时间：<实际信息>

## 适用与选择
适用需求、排除情形、与相邻能力的区别。

## 决策所需信息
信息名称、影响的决策、必需条件、可信来源、缺失处理。

## 信息到参数的规则
依据如何影响选值、用户约束与默认值的优先级、允许的默认值及适用条件、冲突和降级规则。

## 参数规范
实际字段路径、类型、条件必填、限制与示例；和Tool Schema保持一致，已有说明只引用不重复复制。

## 示例和提交检查
正常案例：输入事实→简短选择依据→完整请求。
缺信息案例：补查什么、可否默认、何时停止。
产品边界案例：容易选错的相邻能力或不合法组合。
```

指南不能只有字段表：Schema检查格式，指南指导范围、难度、数量、内容来源等业务决策。不同能力负责人仅维护自己的文件，共用时间、身份、交付规则留在主Skill或对应契约。

## 信息充分性

- 先查影响关键参数的信息，不把所有可获取的用户数据都查一遍。
- 区分明确要求、真实记录、产品默认值与模型推断。
- 不把全部上下文塞进自由文本字段代替参数决策。
- 标记待补充的骨架不是可执行产品规则；提出的候选问题不是已经确认的必填要求。
- 指南未齐不等于能力不可用：本轮需求已明确关键选择且Schema足够时可调用；否则指出缺哪条决策规则或规范，不编造。
- 用户要求不变、接口语义不变时，替换底层实现不应要求改Skill；若枚举、字段或语义变了，仍需同步对齐。

## 提交与结果

提交前检查能力、事实、约束、关键参数映射、引用、Schema与时间。一份明确需求默认一次生成请求；是否允许多产物由业务要求决定，不自行多次试生成或增加推送。

一次调用是正常路径，不是掩盖错误的理由。明确失败且确认可安全重提时再修正；未知写入先核验，不盲目重放。接收、生成、保存、推送和用户消费分别陈述。

模拟实现和验收限制放在本轮记录、Tool说明及测试材料，不嵌入长期业务Skill；仍按通用证据规则报告真实完成范围。

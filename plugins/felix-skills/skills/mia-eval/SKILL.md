# MIA Agent 执行审计

用既有运行证据回答：**这个版本应该做什么；实际工具使用是否正确；本轮流程有没有处理完，是否提前结束。** 只读平台，不重跑评测、不修改 Agent/Skill/Tool、不执行业务写入。默认按 Agent 当轮可见契约审计，Tool 为 Mock 不影响判定；真实持久化、排程和送达不在默认范围。

用户显式调用即选择逐 case 独立子代理分析。默认并发 3，用户指定时使用其正整数 N；取得清单后说明样本数、N 和分析消耗模型 tokens。全部选定 case 都要覆盖。优先直接使用 Agent 工具；仅有 Workflow 工具时加载宿主编排规范实现同一有界队列；缺少子代理能力时说明阻塞。

**已有报告的再处理：**仅重新渲染或修改本次审计范围时，先读[报告修订](references/revisions.md)，走对应分支，不重新启动整轮审计。维护技能本身按[维护验收](references/acceptance.md)离线验证。

## 报告表达

所有读者可见文字用直白、简短、连贯的中文：

- **先说行为。** 写清原要求、实际动作和影响。标题直接说问题，例如“查到了两个任务，只处理了第一个就结束”。
- **沿用设计用词。** 工具名、业务名按固定设计保留，必要时用日常语言解释；内部检查分类留在 JSON，不能当作读者已知的概念。
- **说清环节。** 用设计里的 Agent、Skill、Tool 或具体工具名。尚未定位时写“暂时无法确认问题出在哪个环节”。
- **案例有经过。** 每个问题附相关 case 的任务、关键动作、结果或遗漏及详情链接；链接不代替解释。辅助例子明确标为“例如”。
- **缺证直说。** 说明缺哪段记录、暂时不能确认什么，不补写事实。

汇总依次为：标题与主题切换 → 独立评测 MIA 链接 → 默认折叠的元信息 → 综合表现 → 问题汇总。综合表现含分类数量、分项指标和所有 case 的调用清单完整性表；设计遵循率首行，工具遵循率可折叠下钻到逐工具统计。问题按 P0/P1/P2 排列，每条仅环节、问题、相关 case 经过和链接。汇总不展示独立顺畅通过率行、长公式说明、常驻调用总数区或末尾“全部 case”搜索表，也不写修改建议或验证办法。详情的检查、逐调用、时间线、覆盖与限制及 JSON 证据继续保留。

## 1. 固定目标与审计范围

从执行任务 URL 解析 task_id、space_id，用官方 `evaluation task get` 回读任务，优先从任务配置取得固定 Agent、motif 和版本，再用 `agent get` 核对。用户另给的设计定位与任务交叉检查；能唯一补齐的信息自行查询。只有关联缺失、冲突、浮动“最新版”或数据集对应多个任务时，请求最小选择。精确草稿 agent_id+revision 需与原运行及完整快照一致。

默认关注流程、工具和收尾，用户明确口径直接采用。成功标准仍有会改变判断的歧义且无法从固定版本解决时，分派前调用 `felix-skills:grilling` 集中澄清；不可用时直接问必要问题，不为身份查询机械 grilling。

默认选抓取截止时 ToEvaluate 的数据项，每项一个 case，覆盖全部必要轮次；范围外的已评价、平台失败和运行中项仅在用户要求时纳入。选入后的缺证或分析失败保留占位，多次尝试不增加案例分母。状态筛选、截止与计数核对见[取证规则](references/acquisition.md)。

按[目录与分工](references/dispatch.md)先固定目标项目根，再解析物理绝对路径、确认 Git 忽略和私有权限。默认新建目标项目的 `.eval/mia-eval-<时间戳>-<唯一后缀>/`；显式目录优先。CLI 初始输出先放 acquisition 子目录，RUN_DIR 为空或只含 acquisition 后调用 `prepare_audit.py freeze`。补充规则通过 `--scope-file` 一并冻结，之后 worker、校验和汇总只使用 `runtime/skill/` 的同一快照。

核对冻结正文与本会话实际加载版本；不一致时保留已加载正文和差异，分派前重新加载一致版本或恢复完整对应资源，不拼接新旧文件、不从 Git HEAD 推定执行版本。

**完成条件：**目标、任务、空间/环境、范围、排序、截止、私有路径和成功标准可核对；技能、补充口径、契约与模板固定。

## 2. 理解版本并准备资料

加载官方 `miacli` 的 evaluation、agent-design subskill，遵守项目操作规范，以当前 `--help` 和[取证规则](references/acquisition.md)读取完整分页清单及必要导出。

1. 共享基线只取一次：指定版本的完整 System/User 模板、附加 Skill/Tool Prompt、Schema、模型和固定规则。保留原文件与 SHA-256，历史规则不由最新草稿替换。
2. 写 `baseline/design-summary.json`：目的、场景入口、适用对象与阶段、顺序、必要工具和条件、逐项结果及合法退出；每条附原规则位置，不写 case 预判。
3. 新 manifest 使用 schema v3，历史 v1/v2 保持原契约。`audit_scope` 固定目的、关注点、收尾标准和排除项；六项必查为 identity、design、tool_usage、execution、completion_gate、smoothness。统一 `baseline/audit-brief.json` 区分历史职责与本次允许检查内容，引用补充规则、排除项及[审计标准](references/audit-rubric.md)。
4. 检查完整输入、实际 Prompt、原/改后输出、评分评论、调用、版本、终态、耗时与可见思考的覆盖。运行快照回答“当时看到什么”，固定版回答“要求什么”，差异独立记录。只请求无法获取的必要字段。
5. 生成本例 brief、稳定平台映射及 packet。输入源登记根类型、哈希和自动定位；ID 字符串无损保存，manifest 仅含冻结范围，失败不删分母。

**完成条件：**职责和收尾规则可追溯，选定清单完整或明确部分；每例版本、输入定位和证据缺口明确。

## 3. 独立审计并持续调度

主线程读冻结的[审计标准](references/audit-rubric.md)、[分工模板](references/dispatch.md)及渲染器契约/demo。每例启动全新 worker，返修复用原代理；只交该例资料、共同基线和统一口径，不交其他例结论或主线程预判。

worker 先回传 case_key+ordinal，继续读取精简契约、示例、audit-brief 和本例 packet。**完整输入和全部实际调用必读**；history 已有完整字段时复用，缺什么只补对应 debug；思考与累计 Prompt 按必要定位读取。逐调用规则只从[工具遵循判定](references/tool-call-scoring.md)读取，分轴、实际动作与思考边界、必要查询收尾和补充排除只从[审计标准](references/audit-rubric.md)读取。

逐项账覆盖适用查询、安排评估、生产和通知等阶段。每个对象有实际结果或合法退出依据；最终事件前对账。用自动输入定位填写引用，校验后写 JSON 并用冻结渲染器生成详情 HTML。缺证保持 unknown；初错和实际重试分别保留。

用 `dispatch_queue.py` 记录 reserve → 首条身份核对 → started。初审、预占、返修共用槽位；**报告交付不等于宿主 completed**，只有实际完成通知才释放槽位。拒启释放预占、case 回 pending；按实际容量和 available 持续补位，不能按返回数组顺序绑定身份或改宿主上限。完整事件处理见[调度规则](references/dispatch.md)。失败有限重试一次，仍失败保留占位。

**完成条件：**所有选定 case 有独立结果或失败占位；全部已知调用无遗漏、逐项账完整或明确缺口；报告通过结构与可解析引用校验。进度消息不是完成交付，宿主通知到达后继续核验和调度。

## 4. 核验与汇总

主线程核验身份、覆盖、引用、检查与各轴结论一致性，按 packet 的 `(message_id, tool_call_id)` 集合核对 calls，不只比数量。P0/P1 与矛盾处定点读原引用，退回原 worker 仅修受影响片段；不批读全部日志或 JSONL transcript。归因到最早有证据的失效层，平台背景留在 limitations/platform_context。

按“报告表达”把同环节同具体行为归并到 `synthesis.json.issues`，每条 examples 覆盖全部受影响 case，各例一次。只纳入本次范围内的问题，假设与缺口独立说明，数量及比例由冻结脚本重算：

- 设计遵循率、案例轴与分类口径见[检查统计](references/check-statistics.md)。
- 工具遵循率、逐工具分组与不完整调用清单见[工具统计](references/tool-call-scoring.md)。

用 `summary` 生成汇总并校验全部详情互链；浏览器可用时做一次合成/脱敏页桌面、手机及浅暗主题检查，实测两处折叠。宿主分析 usage 与 MIA 原运行 usage 分开，初审/返修事件和累计快照核实语义后去重，不盲目相加，不更换用户未要求的模型。

**完成条件：**统计可复算，各轴和正文一致，问题有具体经过与证据，全部详情可打开；页面符合确认布局，删展示不删分母或证据。

## 5. 交付

给出汇总 HTML 绝对路径、详情目录、样本与分类数量、设计/工具遵循率、主要问题及范围边界。默认仅本地私有保存，固定离线模板无需联网；身份、签名链接、凭据和整段思考留在私有证据。在线分享需用户明确要求并确认可分享的脱敏内容。

**完成条件：**用户拿到可浏览报告和实际统计，清楚证据不足和未执行项；没有仍可独立推进的工作才暂停，阻塞时说明必要输入。不把技能维护、重渲染或范围修订宣称为重新审计、模型运行或 Agent 效果提升。

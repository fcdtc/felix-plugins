# 报告修订

已有报告再处理时，先分类：**展示变更**只重新渲染；**范围或证据变更**需重新判断受影响项。两者都不是重新运行 MIA。

## 仅重新渲染

1. 确认用户指定的源报告、选定 manifest、synthesis 和目标模板版本；核对最新源码，不用历史冻结副本覆盖维护源。
2. 保持 manifest、checks、calls、findings、verdict 及原证据不变。新建独立私有输出目录，复用原 JSON 输入，由同一目标正式渲染器生成全部详情和汇总。旧页与冻结快照保持原样。
3. 重算新版统计，验证分类、checks/calls 数和状态与源 JSON 一致、全部详情互链有效；不同指标旧名称按 statistics_schema_version/metric_definitions 解释，不靠同名字段猜语义。
4. 标明源报告、模板/脚本哈希和新路径。结论为“离线重渲染验证”，不称新审计或效果改善。

**完成条件：**只有展示/统计命名变化，源判定和证据字节不变，全部页使用同一渲染器且可打开。

## 范围修订或新证据后的重新判定

1. 保存用户明确调整的原文/日期、来源、适用范围、变化项和不变项。保留原规则、原证据和修订前报告，固定补充规则文件与哈希，在新版本 audit-brief 中明确优先级。
2. 定位受影响的检查/调用/发现，优先复用原 worker 定点复核。只撤销或修改由本次范围调整直接影响的理由；其他独立错误和成功仍保留。不把单轮豁免变成全局默认、不恢复被用户排除的旧扣分。
3. 修订判定 JSON、对应正文与各轴，重新校验引用及一致性。单纯范围豁免不增删实际调用、检查行或案例集合；确需证据/清单变化时另记来源与原因，不用改分母提高比例。
4. 在独立版本中重算统计、更新归并问题、生成全部详情和汇总。记录逐项前后变化、旧版位置、补充规则哈希与未变范围。

**完成条件：**每项判断变化可追到用户口径或新增证据，已知独立错误未被连带抹去，原版可恢复。交付称“范围修订后的重新判定”或“新证据复核”；没有模型运行就不称 Agent 优化收益。

未知任务状态先查询原任务，不为修订重复创建评测；必要新审计/模型预算另由用户确认。真实数据仅私有落盘，对外回归用匿名合成数据。

# 实际工具调用判定

本文件是逐调用业务判定的唯一口径。新审计使用 schema v3；v1/v2 按历史契约读取，不能仅改版本号冒充逐调用重审。整体分类仍由原 checks、findings、struggles 判断，逐调用 fail 不自动使 case 整体 fail。

## 1. 全量调用清单

先核对 packet 的 `index.json`、`tool-calls.json` 与本 case 全部轮次。每个实际调用写入 `tool_usage_review.calls`，调用键为 `(message_id, tool_call_id)`，在本 case 内唯一。start/end 及同一调用的多个来源合并为一次；不同消息可有相同 tool_call_id，修正后重新调用另计一次。数组按实际调用顺序保存。

- `inventory_complete=true`：全部必要轮次与调用索引已核对，实际调用无缺项；主线程另按 packet 索引核对复合 ID 集合，不以长度相等替代集合相等。
- `inventory_complete=false`：只列已知实际调用，数量是总量下限；没有拿到的调用总数保持未知。缺身份或无法关联的索引要如实保留缺口、补查，不伪造 ID 来宣称完整。
- 已知调用材料不足时仍列出，`status=unknown`，原因说清缺请求、回包、规则或后续记录中的哪项。unknown 留在已知调用分母内。
- `metrics.tool_calls` 未知用 null；有值须为非负整数。清单完整时须等于 calls 长度；不完整时不得小于已知调用数。汇总只从 calls 计算，不按 metrics 补未知调用。
- 缺 worker 报告同样视为清单不完整。没有已知调用且不完整，不等于已证实零调用。

## 2. 每次调用怎样判断

以该调用当时可见的固定版本规则、请求、回包及必要后续为准。依次核对：

| 要求 | 检查内容 |
| --- | --- |
| 正确工具 | 工具适用于本轮职责和目标对象，未用其他工具绕过限制 |
| 触发条件 | 业务前置、权限和依赖已满足；尚未触发的分支无需凑调用 |
| 参数 | 字段名、类型、枚举、嵌套、目标身份、原对象及数量符合契约 |
| 必要范围 | 查询覆盖所需对象与分页；生产、写入和通知范围符合本轮要求 |
| 结果处理 | 按可见成功、失败、不可用及未知回包处理，完成该调用直接要求的后续 |

全部可判断要求满足为 pass；任一有明确证据的违规为 fail；尚不能判断且没有已证实违规为 unknown。一个调用即使有多个问题也只计一次 fail。pass/fail 必须引用本报告 `evidence_index`；unknown 可以无引用，但必须解释缺口。

### 错误与恢复

- **平台失败不自动等于调用错误。** 请求、范围和结果处理正确，服务返回失败、不可用或超时也可 pass。因参数错误被拒绝则 fail。
- 首次错误调用及修正重试分别记录；首次 fail 保留，不能因最终修好改成 pass。必要重试及合理核验可 pass；恢复过程照原标准写 struggles，不把已恢复调用错误自动变成整体不通过。
- 充分结果已经取得，后续重复调用已证实没有增加信息且没有必要时，可 fail；不能仅因调用多、耗时长、再次读取或有重试就扣分。尚未证明重复无必要时，保留规则和证据边界。

### 前置、误读与遗漏如何归到调用

- 未核对必要前置便新增记录，**首次相应生成调用**为 fail；纯消息新增则归首次相应 push。历史查询请求本身若正确仍可 pass；已成功且正确处理的所有下游通知不连带判错。每个下游调用自身另有违规时再独立判定。
- 回包明确写出结果，Agent 却误读或认领相反状态，归到返回该结果的对应调用；引用回包及处理证据。
- 查询返回必须直接继续的分页而未做，归该查询的必要范围/结果处理为 fail。后续其他调用自身仍独立判断。
- 应做但从未实际调用的动作不造一条 calls、不计调用分母，仍按 design、execution、completion_gate 检查遗漏。不能用高调用正确率遮蔽流程漏项。

### 默认范围

只审计实际工具使用，不评价最终回复的文风或内容；最终事件仍用于判断结果处理、流程收尾及是否提前结束。Tool 为 Mock 不影响判定，不额外要求数据库落盘或实际送达。工程注入字段不算模型漏填；请求失真尚未定位时保留调用链缺陷，不直接归模型。

## 3. 字段与统计

v3 case 必需：

```json
{
  "tool_usage_review": {
    "inventory_complete": true,
    "calls": [
      {
        "message_id": "synthetic-message-1",
        "tool_call_id": "synthetic-call-1",
        "tool_name": "synthetic-tool",
        "status": "pass",
        "reason": "请求符合约定；服务不可用后按规则交接受阻并继续独立事项。",
        "evidence_refs": ["e-result"]
      }
    ]
  }
}
```

对象及调用项仅允许上述字段。ID、工具名、status、reason 为非空字符串，evidence_refs 为字符串数组；引用本报告现有 evidence_index，不另建证据体系。

**工具正确使用率 = 全部选定案例中正确实际调用数 / 全部实际调用数。** 汇总 pass、fail、unknown 的调用总数加权，不取案例平均。例如一个案例 1 次调用错误、另一个案例 9 次调用正确，正确率为 9/10=90%，不是 50%。零调用为 N/A。

有任何选定案例清单不完整时，显著展示不完整 case 数、已知调用数下限及“已知调用正确占比（非全量调用率）”，无法声称全量工具正确使用率，未知总量不补写。分工具或每 case 的计数也来自已知 calls。

design、execution、completion_gate 仍按全部选定案例统计。工具遵循率另按详情页全部 `checks` 条目计算，定义见[检查条目统计](check-statistics.md)；它不使用 calls 或 case 平均值。同名 `checks.tool_usage` 保留为必要案例检查，参与整体判定，并作为一条普通检查计数。v1/v2不伪造逐调用数据，历史报告不自动重写。

HTML 仅展示调用顺序、tool_name、中文判定和自然中文原因，原始 message/tool_call ID、证据原文和整段思考留在私有 JSON/证据文件。原因按 SKILL.md“报告表达”脱敏，写具体行为，不用内部判定词代替解释。

# Skill 维护验收

修改本技能时，按下表验证文档、渲染器与统计，不调用真实评测或模型。真实评测审计需用户提供任务及版本，不能以合成页宣称线上效果通过。

## 命令

从仓库根运行，输出目录必须是新目录：

```bash
python3 -I -B -m unittest discover -s plugins/felix-skills/tests -p 'test_mia_eval_*.py'
python3 -I -B plugins/felix-skills/skills/mia-eval/scripts/render_report.py demo --out /private/tmp/mia-eval-demo-new
python3 scripts/validate-skills.py
claude plugin validate ./plugins/felix-skills
git diff --check
```

## 不变式

| 场景 | 验收要求 |
| --- | --- |
| 默认输出路径 | 使用当前项目根目录的.eval下独立运行目录，不使用Skill安装位置；Git忽略生效，历史目录不覆盖，显式输出目录优先 |
| 默认待评价范围 | 待评价45、平台失败5时默认选45个，分母45；不把平台失败数当作审计不通过数。scope_complete按待评价范围判断，用户明确扩大范围时才纳入其他状态 |
| 并发参数静态走查 | 未指定时N=3；指定1时单槽位，指定8时按8个槽位分派，不被默认3截断；剩余case不足N时全部启动，完成一个立即补位 |
| 实际并发受限 | 只依据宿主容量限制或实际CLI限流处理，说明指定值、实际可用值及依据；无效参数请用户修正，不静默回落默认值 |
| 四类合成case各一项 | 顺畅通过率为1/4，四类互斥，总数为4 |
| 少一个worker结果 | 该case保留证据不足及可打开的占位页，分母不变 |
| 版本不同或关键轨迹缺失 | 不进入顺畅通过 |
| 请求失败后修复成功 | 无遗留业务偏差时计恢复；不能因最终成功遮蔽重试 |
| 已确认业务缺陷 | 即使worker填pass，也不能计顺畅通过 |
| 仅有假设或思考缺失 | 不直接判业务失败；必要证据未知按覆盖规则处理 |
| 零case | 比率N/A，不显示100%或除零 |
| 重复/额外case、非法JSON、未知证据引用 | 明确报错，不静默忽略 |
| 注入HTML、脚本URL、目录穿越键 | 作为文本转义或拒绝，不能执行或越目录写入 |
| 缺少指标 | 显示未返回，不补0、不估算费用 |
| 部分取证清单 | 显著提示仅对已获取/已选择case统计，不称全任务通过率 |
| 多轮/重试 | 同case全轮证据审计，保留原失败，不按日志事件数量扩分母 |
| 模板更改 | 所有逐case及汇总由同一渲染器生成；旧HTML与当前JSON不一致时必须明确重建 |
| case阅读表达 | 检查要求用中文，应该怎么做/实际做了什么用具体自然短句；页面不展示检查内部ID、证据列、证据短引用表及设计与业务偏差区块；JSON证据和findings校验、判定及建议生成保持有效 |
| v2 Agent流程口径 | manifest有Agent目的、关注点、完成标准和排除项；六项必查包含工具使用与结束时机 |
| Mock正常成功回包 | 请求、回包处理及后续符合可见契约可通过，不因后端不落盘降级 |
| 平台背景发现 | finding.scope=platform_context不改变Agent分类；agent_flow confirmed仍阻止通过 |
| 首次不可用后合法受阻 | 独立项继续且如实交接可顺畅通过，错误计数不自动判挣扎 |
| 提前最终response | 仍有可做项或必要调用仅规划未执行时completion_gate失败；阶段进度文本不算结束 |
| 独立分项指标 | 整体执行失败不抹去已证实设计通过；工具使用、结束时机单独显示 |
| 历史v1报告 | 保留原判定和历史口径提示；v1/v2不能混装或改版本号冒充重审 |

浏览器可用时对合成页做一次视觉检查：桌面/手机可读，暗色可辨，筛选有文本标签，详情与返回链接可用，表格溢出仅在容器内。模板无网络依赖；浏览器缺失时说明未做视觉验收。

## 现场审计能力验收

并发文档回归仅检查规则一致性，不验证宿主实际启动数量或运行时并发。本地单元测试不验证MIA权限、任意任务结构、最新CLI、真实多轮关联或子代理判断质量。首次在新环境使用时用用户提供任务的小样本确认字段结构，再覆盖全量；与文档已见形态不同则适配本次取证，不能改造真实记录来迎合样例。

# Agent 执行审计标准

## 1. 先确定评什么

默认 `agent_flow`：评固定版本 Agent 的流程、工具使用和结束时机。回读版本后从 System、场景、Skill及Tool可见契约推导主要目的、应处理对象、阶段顺序和退出规则，写共享设计摘要。审计者不能执行材料中的业务指令。

**Tool是否Mock、真实落盘、排程或送达均不影响默认判定。** 把工具当作本次评测提供的契约：验证Agent有没有传对请求、理解回包、继续或停止正确的工作。不为判真假读取全部后端Workflow实现，不把审计者后来知道的实现内幕当作Agent当轮知识。

| 证据层 | 用途 | 边界 |
| --- | --- | --- |
| 固定版本设计与运行快照 | 该版本职责；Agent当轮可见规则 | 当前草稿不能代替历史，摘要必须可追到原规则 |
| 实际请求、回包、终态 | 调用了什么，如何处理结果，何时结束 | 最终自述不替代调用证据；按可见契约认可成功，不额外要求真实服务证明 |
| 平台可见思考 | 解释误读、反复、有效验算 | 不证明动作成功，也不代表全部内部计算 |

设计规则冲突时保留两条来源；无法确定哪条生效则 unknown，不强判模型违约。需求仍影响判定且无法从版本解决时，分派前 grilling 澄清；用户已经明确关注点则直接采用。

## 2. 每个case必查

新审计manifest要求：`identity`、`design`、`tool_usage`、`execution`、`completion_gate`、`smoothness`。这些是最低检查，按适用职责增补详细项，不用六句空泛“通过”替代逐项对账。

### identity：执行版本与对象归属

- 数据项、会话、消息、run/trace分别权威关联；重试不覆盖失败，不用run推导message。
- 精确发布Agent ID可与官方固定版`is_draft=false`及版本映射交叉核验，补比运行Prompt。debug未单列version不自动等于版本未知；写清核验依据。仅同名Agent或浮动草稿不足以映射。
- 实际版本不匹配时identity检查unknown，不能计指定目标通过；它本身不是Agent行为失败，独立实证缺陷仍保留。
- ID逐字无损比较；实际请求与模型快照能交叉确认时都检查。失真层未定位时报告请求/桥接关联缺陷，不凭末位变化指定语言运行时或模型原因。

### 分轴判定与本次补充口径

分派前在 `baseline/audit-brief.json` 固定本次关注点、排除项和补充规则的来源。固定版本规定 Agent 应做什么；用户明确的审计口径规定本次检查哪些行为。摘要不能新增职责，也不能把当前草稿或新业务设计拿来回评旧版。补充口径与原规则仍有影响结论的歧义时，先澄清或保留 unknown。

各轴各自回答一个问题：

| 轴 | 判断依据 | 不应由另一轴自动推导 |
| --- | --- | --- |
| design | 是否满足业务规则、范围、前置条件与权限 | 结束正常不代表设计遵循 |
| tool_usage | 工具选择、参数、分页、回包及依赖处理是否正确 | 工具成功不代表前置条件已满足 |
| execution | 应处理对象和实际新增对象是否都有结果，必要后续是否收尾 | 已确认设计违规不自动等于有事项遗漏 |
| completion_gate | 最终事件前是否仍有可做项、未返回结果或仅规划的动作 | 较早的准入错误不自动等于提前结束 |
| smoothness | 是否发生实际返工、无效重试或无新证据反复 | 首次不可用、合理择型或一次指南读取不自动算挣扎 |

**交叉例（匿名合成）：**固定规则要求新增前查重，Agent 查询失败后仍生成一份内容，但已取得生成结果、提交唯一通知且无其他对象遗漏：design、tool_usage 为 fail；execution、completion_gate 可 pass，整体仍为不通过。若还有第二项未处理就结束，execution、completion_gate 另有独立 fail 依据。轨迹缺失无法对账时为 unknown，不能用最终自述补通过。

**依赖判断：**技能或指南预读只表示取得规则。以实际选择、写入、生产、通知动作及其依赖回包判断是否提前执行；有益预读本身不作为顺序失败。固定版本若确有对读取动作本身的业务约束，引用该约束单独判断，不把“进入某阶段”自行扩成“此前不可读规则”。

### design：这个Agent应当做什么

逐场景列出路由、对象范围、必需阶段、顺序、门槛、权限及合法退出条件。每阶段写预期、实际和引用，检查：

- 本轮适用职责均被处理；未触发的分支不需要凑调用。
- 保持、静默、受阻是否有规则允许的依据；独立项是否继续。
- 资料来源与冲突保留，未知不变无/零/已解决，原要求与必要材料不丢失。
- 动作不越权，成功项不重复，明确依赖顺序不被“独立可并行”覆盖。
- 制品正文仅在Agent负责准备、且本次关注点包含内容时审；未返回实物不要求验证PDF版面或下游教学质量。

### tool_usage：是否正确使用工具

- 正确工具、适用触发条件、字段名/类型/枚举/嵌套、身份与原对象一致；工程注入字段不判模型漏填。
- 按需要范围完整分页，失败空数组不当完整空集，完整已得结果复用。
- 按可见契约处理成功、失败、不可用、超时/未知；未知结果先核验原操作，失败仅阻断依赖项。
- 可修正错误在允许次数内修正，保留原失败。不可用分支按设计返回受阻，不能擅自替代素材或跳过硬门槛。
- **Mock正常回包按契约可认可。** 不因生成随机短ID、摘要成功文字或通知模拟实现判失败。只有可见契约要求原Task回显而实际错配、输入ID失真，或回包明确失败却认领成功，才是Agent/调用链缺陷。若Tool允许新内部ID，不强行与源Task比较；语义不清则unknown而非猜测。

### execution：本轮流程是否处理完

这里的“完成”指Agent职责收尾，不是后端真实业务发生。给每个应处理对象建结果账：阶段/对象→实际动作→回包→后续状态→退出依据。

| 观察到的情况 | 流程完成判定 |
| --- | --- |
| 合法请求得到契约成功，必要后续均完成 | pass；Mock也相同 |
| 规则允许无需行动，依据明确 | pass |
| 能力不可用且规则允许受阻退出，报告具体缺口并继续所有独立项 | pass；产物未生成不等于流程遗漏 |
| 仍有可执行项未处理，或依赖结果尚未知却认领全部完成 | fail |
| 轨迹不全，不能确认每项结果 | unknown |

成功回包不额外追查数据库或送达；但Agent职责内的对象关联、失败处理和最终对账仍要检查。输出按实际任务数、状态、失败/重试次数与日期对账。人工改后输出/评分作为独立背景，不覆盖原执行。

### completion_gate：有没有提前最终response

以本轮完整终态及必要前文检查，不能只看最后一段文字。

1. 建出应处理对象和阶段清单，定位**最终response／RUN_FINISHED**。
2. 检查最终结束前：必要工具是否仅规划未调用、异步请求是否尚未得到设计要求的结果、部分成功后是否漏掉其他独立项、能力失败后是否仍有可继续工作。
3. 有未完成项时，引用具体对象、应执行阶段、最后可见状态及最终事件；仍有可做任务却结束为fail。证据不足为unknown。
4. 规则允许的静默、受阻及全部职责处理完后的总结为pass；会话中途“我先查询…”等进度文本不等于提前结束。工具契约仅要求异步提交时，提交成功可结束，不额外等待下游送达。

合理受阻与提前结束的区别是：**退出规则是否允许、缺口是否如实交接、其他独立项是否已处理完**，不是最终有没有response。

### smoothness：合理工作与执行挣扎

smoothness检查表达“证据足以判断”；观察到完整返工时check可pass而verdict=recovered/struggling。

- 参数返工、错误枚举、同操作无效重试、充分结果重复拉取、没有新证据的反复决策放struggles。
- 已知不可用仍无必要探测可算挣扎；首次按设计查询才发现不可用、正确受阻和继续不算挣扎。
- 内容独立验算、核验必要事实、合理分页不因耗时长或调用多算挣扎。
- 工具错误/不可用计数只作资源事实，**不自动决定顺畅性**。返工修正且无残留违约为恢复；未恢复硬错误为不通过。
- 可见思考里纠正的错误念头不当作已执行错误；缺思考不编造，充分实际轨迹仍可通过。

## 3. 发现、归因与统计

每个pass/fail检查有规则与执行引用，unknown说明缺口。发现短引脱敏，不复制整段思考。

新报告finding填写`scope`：

- `agent_flow`：影响本次Agent职责、工具使用或收尾；仅这类confirmed发现参与不通过。
- `platform_context`：后端实现、Mock、部署或真实送达背景；不参与Agent判定，也不计入默认问题汇总涉及的case数。默认无需主动取得，可用limitations简述。

纯恢复返工及性能建议放struggles。P0为关键对象关联/越权/关键收尾错误；P1为阶段遗漏/硬门槛/内容范围违约；P2为次要规范或结果陈述错误。归最早已证实层：工程输入/调用适配→Tool可见契约→SP编排→Skill→User模板→模型预算。未定位问题不强归模型；不以换模型或“再强调Prompt”替代能力事实。

分母为冻结的全部选定case，默认只含待评价项；范围外的已评价、运行失败和运行中项不进入分母。选定case中的多轮硬失败保留，取证或worker失败也保留占位，但重试不增加分母。固定脚本计算四类；设计/流程完成轴分别统计，另一轴失败不抹去本轴证据。工具正确使用、结束时机另展示必查结果。历史schema报告按原口径读取，不能换新标签冒充重审。

计数按唯一tool_call_id，start/end算一次；失败调用、批次和case分开。usage去重不叠累计快照；缺失null。工具耗时和并行关键路径不混算，不能用总耗时减累加工具时间得思考时间。未经重跑不编造优化收益。

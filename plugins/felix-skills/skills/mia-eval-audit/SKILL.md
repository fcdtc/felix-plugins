# MIA 评测链路审计

一次只读审计，适用于任意 MIA Agent。比较**设计基线、可见决策、实际执行**，回答每个 case 是否遵循设计并顺畅完成，以及应在哪一层优化。使用现有运行证据，不重跑评测、不修改 Agent/Skill/Tool、不执行业务写入。

用户显式调用本技能即选择逐 case 子代理分析；先说明样本数与并发上限、分析会消耗模型 tokens。默认最多并发 3 个子代理，覆盖全部选定 case，不静默抽样。没有子代理能力时交代阻塞，不能用主线程批量阅读冒充独立审计。Agent工具可用时直接调度；若宿主只有Workflow编排工具，先加载其官方编排规范，再实现同一有界队列，不递归派生子代理。

## 1. 固定输入与范围

取得两个必需输入：

- **Agent 固定版本定位**：设计页 URL 或 motif_id、agent_id、发布版本。版本号/所属 motif 能从用户给定 agent_id 权威回读时自行补全；只有 motif、浮动草稿或“最新版”时，请用户指定固定目标。精确草稿 agent_id+revision 仅在该评测确实运行同一草稿且有完整快照时适用。
- **评测任务 URL**：应能定位 task_id 和 space_id。只有 dataset_id 的数据集 URL 没有执行轨迹，先用官方 CLI 查关联评测任务；多个候选无法唯一对应时，请用户选执行任务。不要索要已能从 URL 读出的 ID。

用户未限定时覆盖该任务所有数据项及其轮次。一个数据项及其关联完整多轮执行为一个 case；同一 case 的重试不增加分母。页面序号只用于展示，稳定关联见[取证规则](references/acquisition.md)。

默认输出到仓库外新的私有目录，例如系统临时目录下独立的 `mia-eval-audit-*`；用户指定位置时尊重并提醒原始材料含敏感信息。冻结本次抓取截止、版本、样本集合和排序。后续新产生的运行不混入本次分母。

完成条件：目标版本、任务、空间/环境、case范围、私有输出路径明确；有歧义的必要输入已解决。

## 2. 获取清单与设计基线

先加载环境中的官方 `miacli` 及评测、Agent 设计 subskill，遵守目标项目的操作规范；命令能力以当前 subskill、`--help` 和响应为准。按[取证规则](references/acquisition.md)读取任务详情、完整分页记录及必要导出。

- 默认 **URL 优先、CSV 可选**。逐项检查输入、输出、改后输出、评分评论、调用、思考、版本和耗时的覆盖；只有实际缺字段或权限时再要求最小补充，不能承诺任意任务与 CSV 完全等价。
- 回读指定版本及固定 Skill/Tool 依赖，包含完整 System、User 模板、附加 Skill/Tool Prompt、输入输出 Schema、可达 Skill/reference 和模型配置。共享基线只取一次，保存文件及 SHA-256。
- 运行时快照优先说明“当时看到了什么”；固定版本回读说明“该版本要求什么”。两者不一致单独记录。当前草稿或最新文档不覆盖历史基线。
- 原始证据不可变；按[目录约定](references/dispatch.md)创建 manifest、共享基线与每 case 资料包。所有 ID 用字符串保存，不经浮点数转换。

完成条件：manifest 覆盖每个选定 case，包括失败、运行中和缺失项；每个 case 均有明确版本关联或缺口；CSV/URL 字段覆盖有记录。未能拿到完整总量时显著标记“部分清单”，不能宣称全量通过率。

## 3. 逐 case 独立分析并生成详情页

读取[审计标准](references/audit-rubric.md)、[子代理分工](references/dispatch.md)与[固定渲染器](scripts/render_report.py)的 JSON 校验及合成示例。每个 case 启动一个全新子代理；同一 case 返修复用原子代理。

给子代理的是该 case 完整上下文、基线和统一标准，不附主线程预判、不附其他 case 的结论。每个子代理负责：

1. 按需取得本 case 原始 history/debug，补齐必要证据，所有平台读取仍走官方 CLI。
2. 从该版本职责推导适用检查项，逐项对照实际请求、回包和输出。
3. 结合平台返回的可见思考分析误读、反复决策、有效验算及无效重试；思考缺失不编造。
4. 写 `reports/<case_key>.json`，用本 Skill 的固定渲染器独立生成 `site/cases/<case_key>.html`。
5. 回传三轴结论、重要发现、证据缺口和文件路径，完整原始日志留在私有文件中。

主线程持续调度剩余 case，不重复阅读每个子代理已负责的全量日志。子代理超时/失败时查原任务，有限重试一次；仍失败保留证据不足占位，不移出分母。逐 case 页面由固定模板渲染，子代理不自行改布局。

完成条件：每个 manifest case 均有独立子代理结果及详情页，或明确的失败/缺失占位；无人把“已提交”“保存成功回包”“已送达”“任务达成”混为一谈。

## 4. 校验、归并与统计

主线程交叉核验版本、完整性、检查项与结论一致性；对影响判定的 P0/P1 发现定点读取引用证据，必要时退回原子代理修正。主线程不为了统一结论改写原始失败或掩盖数据缺口。

将重复根因按**问题层+失效机制**归并，写 `synthesis.json`；每条建议保留影响 case、证据、建议改动及回归断言。只出现一次的问题也可以报告，不为凑例数找无关 case。跨 case 频率由引用的 case 去重计算，不能将同一 case 三次工具失败写成三个失败 case。

统计由渲染器从 manifest 与逐 case JSON 重算：

- **顺畅通过率 = 符合设计、完成任务且无执行挣扎的 case / 全部选定 case**。
- 四类固定为“顺畅通过、恢复/挣扎、不通过、证据不足”，互斥且总数等于分母。
- 正确的静默/无需行动可通过；可恢复的参数错误不算顺畅通过；明确业务违约即不通过；没有证据证明完成则不补成通过。
- 同时展示分析覆盖、设计遵循、任务完成和思考覆盖；缺少分母或分母为零显示 N/A。详细判定以报告契约为准。

使用脚本的 `summary` 子命令生成 `site/index.html`；逐 case 页面互链并能返回总览。禁止模型手填最终通过率。运行本地链接/数据校验；可用浏览器时检查一次合成或脱敏页面的桌面/手机布局，修复错误后完成，不发起真实 Agent 运行。

完成条件：计数可复算、全部详情链接可打开、建议可追到 case 与证据、失败/恢复/未知未被隐藏，模板版本和证据覆盖已记录。

## 5. 交付

给出汇总 HTML 绝对路径、逐 case 目录、总数与顺畅通过率、最优先的建议及重要证据边界。固定模板无需联网，直接打开 `site/index.html` 即可逐 case 浏览。

报告默认仅本地保存。内部身份、学习记录、签名链接、凭据及整段原始思考留在私有证据目录；HTML 仅保留去标识概要、必要短证据与安全定位。用户明确要求在线分享时，先确认允许发布的脱敏内容，再按宿主的文档/Artifact能力发布整套页面；没有发布能力时交付本地包，不能把本地路径称为在线 URL。

完成条件：用户拿到可浏览的实际文件及统计，不只是终端计划；说明未执行的平台修改、重跑和外部发布。

# 领域文档

本仓库采用 single-context 布局：
根目录 `GLOSSARY.md` 记录领域术语，`docs/adr/` 记录架构决策。

## 探索前读取

- 读取根目录 `GLOSSARY.md`。
- 如果存在根目录 `GLOSSARY-MAP.md`，改为按其索引读取与主题相关的术语表。
- 读取 `docs/adr/` 中与当前工作范围相关的 ADR；
  如果仓库后来采用多上下文布局，也检查 `src/<context>/docs/adr/`。

文件不存在时，静默继续，不将缺失列为问题，也不预先建议创建。
术语或决策明确后，由 `/domain-modeling` 按需创建领域文档。

## 使用领域术语

工单标题、重构建议、假设和测试名称中的领域概念，
使用术语表定义的名称，避免改用术语表明确排除的同义词。

所需概念尚未收录时，先判断是否引入了项目不使用的概念；
如果确有缺口，记录为后续 `/domain-modeling` 的输入。

## 明示 ADR 冲突

建议与现有 ADR 冲突时，明确引用该 ADR 并说明重新讨论的理由，
而不是静默覆盖既有决策。

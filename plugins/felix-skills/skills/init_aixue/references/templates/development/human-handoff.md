# 人工协作场景与模板

用于平台操作确实需要人工时准备交接。授权、工具边界、批次原则和动态证据归属以[平台操作](platform-operations.md)为准；RPC 发布阶段门禁见[RPC 接入发布链](mia-rpc-tool-host-release.md)，Host 增量保护规则见[Agent 受管发布](mia-agent-release.md)。

## 交接判定

先加载对应技能、检查当前 CLI 帮助、回读目标状态并排查错误。参数未知、未查看帮助、一次调用失败或请求仍在运行，不是人工交接理由。当前工具支持且已获授权的事项由 Agent 完成；以下矩阵仅描述交接条件，不声明某版本 CLI 永久缺少能力。

| 场景 | Agent 交接前完成 | 人工触发条件 | 模板 |
| --- | --- | --- | --- |
| MIA RPC Version | 核对后端、BAM／Overpass 来源与目标方法 | 当前 CLI 无所需版本创建入口，或平台要求真人确认 | [创建 RPC Version](#创建-mia-rpc-version) |
| Workflow RPC snapshot | 读取 WIP、定位节点、备份映射并核实新 schema | 必须在页面重选 Version／方法，且当前 CLI 无等价能力 | [刷新 snapshot](#刷新-workflow-rpc-snapshot) |
| Skill 固定版本 | 保存并回读完整草稿与 revision | 当前 CLI 无 Skill 发布入口，或平台要求真人发布 | [发布 Skill](#发布-skill-固定版本) |
| Tool 固定版本 | 回读固定 Workflow，准备完整 Tool 配置及差异 | 当前 CLI 无所需创建／编辑／发布入口 | [发布 Tool](#创建或升级-tool-固定版本) |
| Host 后继草稿 | 回读指定父版本、最新状态及完整资源基线 | 当前 CLI 无从指定发布版本创建后继草稿的入口 | [创建 Host 草稿](#创建-host-后继草稿) |
| HTTP Header 身份验收 | 核实最终版本链、身份契约、测试矩阵及透传能力 | 当前工具无法覆盖真实入口，或真实登录身份必须由用户操作 | [身份验收](#真实-http-入口身份验收) |
| 登录、审批、权限 | 排查认证／权限原因，整理正式入口及申请范围 | 必须真人登录、审批，或用户需要自行提交权限申请 | [登录与审批](#登录审批与权限协助) |

## 交接前检查

- 目标空间、环境、资源与授权范围明确，上一阶段门禁已通过。
- 已核实当前能力缺口或真人要求，记录相关帮助／错误依据。
- 提供可定位目标的真实 URL 或已核实菜单路径；页面入口尚未知时先查明，无法查明则明确阻塞，不编造链接。
- 将下方模板所有 `<占位符>` 替换为已核实值；Schema、描述、发布说明和测试请求完整给出，用户不负责推导。
- 明确本次只保存草稿、创建版本或正式发布；模板本身不授权写入或扩大影响范围。
- 不把 JWT、Cookie、生产凭证或真实身份原文放进交接消息；测试 fixture 使用获准的受控值。

## 依赖批次示例

只交接当前确实需要人工的阶段，工具已支持的步骤从人工批次移除。每批回复后先回读验证，再推进依赖其结果的批次。

1. 创建 RPC Version → Agent 回读来源、版本和方法。
2. 各 Workflow 刷新 RPC snapshot（不同图可同批）→ Agent 恢复映射，按目标 debug、发布并回读。
3. 发布 Skill 与各 Tool（互不依赖时同批）→ Agent 回读固定版本及 schema／Workflow 绑定。
4. 创建 Host 后继草稿 → Agent 合并固定依赖、保留非目标资源、发布并回读。
5. 真实入口身份验收 → Agent 回读 Session／调用轨迹、日志与业务状态。

不同图或组件可以同批；同一 Host 的草稿更新串行执行。BAM／Overpass 的必要审批应在对应阶段完成，不跨过门禁等待最后一批补办。

## 固定消息与失败回复

实际交接按下面格式连续列出事项，不重复已完成步骤。各场景模板的内容填入对应事项：

```text
## 人工批次 <N>

### 事项 1：<结果名>
入口：<真实 URL 或已核实菜单路径>
操作：
1. <动作及完整字段值>
2. <明确保存草稿／创建／发布动作及保持不变项>
回复：`<字段>=<值>；<字段>=<值>`

### 事项 2：<结果名>
入口：<真实入口>
操作：
1. <动作>
回复：`<字段>=<值>`
```

字段不存在、选项不符、基线版本变化或平台报错时停止该事项，保留现场并回复（错误原文先脱敏）：

```text
事项=<名称>；状态=blocked；页面字段=<实际字段或选项>；错误=<脱敏错误原文>
```

某类标识页面未返回时写 `not_returned`，返回可用页面 URL 便于 Agent 定位；不猜 ID／版本。Agent 随后用当前支持的 CLI 查询或平台响应补齐证据。只返回“完成”不能满足版本门禁。

回读发现不一致时只交接需修正的字段；基线已变化则先重新读取、比较和合并。发布态结果不明先查原发布，不要求重复点击发布。

## 创建 MIA RPC Version

**准备：** 确认目标空间、PSM、已推送分支、IDL commit、Overpass 产物与方法清单；查询既有版本，排除本次资源已创建。准备实际创建入口和是否允许改变 Online 指针。

```text
### 事项：创建 RPC Version
入口：<目标空间的 RPC 版本管理 URL 或已核实菜单路径>
操作：
1. 核对空间=<SPACE_ID>；查询服务=<PSM>。
2. 新增版本，选择分支=<REMOTE_BRANCH>；来源应对应 Agent 已核实的 <OVERPASS_ARTIFACT_OR_DIGEST>。
3. 创建；保持 Online 指针不变，本次不切换线上版本。
4. 检查目标方法：<完整方法清单>。
回复：`rpc_version=<实际版本>；methods=<各方法是否可见>；url=<版本页面 URL>`
```

**回读标准：** 版本对应目标 Overpass 来源，方法及请求响应 schema 完整且可供 Workflow 选择。需要切换 Online 时另行明确授权并修改交接动作，不能由“创建版本”隐含授权。

## 刷新 Workflow RPC snapshot

**准备：** 回读指定 WIP、节点 ID／别名、最新锁值及旧映射；确认固定 RPC Version／方法与 schema。页面重选可能重置请求模板，Agent 保存映射基线，后续负责恢复。

```text
### 事项：刷新 <WORKFLOW_NAME> RPC snapshot
入口：<指定 Workflow WIP 设计页 URL>
操作：
1. 核对 motif=<MOTIF_ID>；WIP graph=<GRAPH_ID>；选择节点=<NODE_ALIAS_OR_ID>。
2. 仅修改：服务=<PSM>；版本=<RPC_VERSION>；方法=<RPC_METHOD>。
3. 保存 WIP，不发布；请求模板被平台重置时保持重置后的现状，交由 Agent 恢复映射。
回复：`motif_id=<ID>；graph_id=<实际 WIP ID>；wip_saved=true；method=<方法>；url=<设计页 URL>`
```

**回读标准：** snapshot 的版本、方法和 schema 生效，非目标节点不变。Agent 在最新 WIP 上恢复变量映射，核对引用与错误出口，再按获准目标 debug／发布；人工保存不直接完成发布门禁。

## 发布 Skill 固定版本

**准备：** 保存完整 Skill 文件树并回读目标 Component、revision 和内容摘要；确认发布说明与目标草稿，排除未合并的并发修改。

```text
### 事项：发布 <SKILL_NAME> 固定版本
入口：<目标 Skill Component 页面 URL>
操作：
1. 核对 component=<COMPONENT_ID>；打开草稿 revision=<REVISION>。
2. 发布说明：<完整说明>。
3. 发布；正文、配套文件和其他配置保持不变。revision 与清单不符时停止。
回复：`skill_component_id=<ID>；skill_version=<实际固定版本>；url=<发布版本 URL>`
```

**回读标准：** 固定正整数版本的内容和文件树符合预期，确实来自核实的草稿。得到版本后再由 Agent 挂载固定依赖；草稿 revision 不能代替发布版本。

## 创建或升级 Tool 固定版本

**准备：** 回读已发布 Workflow 的 motif／固定版本；创建时准备完整配置，升级时回读既有 Tool 基线和差异。提供严格 Schema、描述、风险等级、超时、权限及发布说明，字段格式以当次页面契约为准。

```text
### 事项：发布 <TOOL_NAME>
入口：<目标 Tool Component 或新建入口 URL>
操作：
1. <新建 Tool／打开 component=<COMPONENT_ID> 的指定草稿>。
2. 仅修改：
   - 名称：<名称>
   - 描述：<完整描述>
   - Workflow：motif=<MOTIF_ID>；固定版本=<WORKFLOW_VERSION>
   - 风险等级：<已确认值>
   - 超时：<数值及单位>
   - 输入 Schema：<完整可粘贴 JSON>
   - <其他必要且已确认字段>：<完整值>
3. 切换 Workflow 后，再完整覆盖并核对输入 Schema；不绑定草稿或浮动最新版。
4. 发布说明：<完整说明>；发布。其他配置保持不变。
回复：`tool_component_id=<ID>；tool_version=<实际固定版本>；url=<发布版本 URL>`
```

**回读标准：** Tool 固定版本、Workflow 绑定及 schema 一致，权限／风险／超时符合预期，非目标配置保持。仅草稿保存或字段漂移时不更新 Host。

## 创建 Host 后继草稿

**准备：** 回读指定 Host 发布版本、最新草稿状态与资源全集；核对父版本是否仍是预期基线。若已有可用后继草稿先评估复用，避免重复创建。

```text
### 事项：创建 <HOST_NAME> 后继草稿
入口：<指定 Host 发布版本 URL>
操作：
1. 核对 motif=<MOTIF_ID>；发布 Agent=<PUBLISHED_AGENT_ID>；父版本=<PARENT_VERSION>。
2. 使用“基于此版本编辑”或当次页面等价入口创建后继草稿。
3. 不修改 Skill／Tool 或其他配置，不发布。父版本或已有草稿状态与清单不符时停止。
回复：`motif_id=<ID>；draft_agent_id=<实际 ID>；parent_version=<父版本>；url=<草稿 URL>`
```

**回读标准：** 草稿父版本和资源基线一致。Agent 获取真实锁值后串行合并目标增量，确认固定依赖和非目标资源完整，再按授权发布并回读；不创建独立 Agent 代替共享 Host 更新。

## 真实 HTTP 入口身份验收

**触发条件：** 当前 CLI 的 Header 能力和下游透传契约无法证明请求经目标真实入口，或必须使用真人登录身份。先核实当前技能／帮助，不能沿用“CLI 永远不能传 Header”的历史判断；也不能把全局 Header 支持视为端到端认证已支持。

**准备：**

1. 回读固定 Host／Skill／Tool／Workflow 及后端 commit、SCM 制品、部署和实例，确认测试落到目标版本。
2. 从本次身份契约确认 Header 名、服务端实际身份来源、允许的受控 fixture 或真实账号流程；不迁移其他项目的 persistent key、fallback 或业务规则。
3. 准备完整请求、预期 Tool 和断言；按契约选择身份 A／B、缺失／异常身份等矩阵。适用时包括各自资源可读、跨身份不可读及幂等反例，具体字段由本次业务定义。
4. 优先为各身份／关键反例使用新 Session。若测试要求临时配置变更，先确认恢复方案与授权，验证部署态；结束后恢复并回读最终配置，不只恢复本地文件。

```text
### 事项：<身份 A／身份 B／缺失身份／异常身份> 验收
入口：<已核实的真实 Host HTTP 入口>
操作：
1. <使用指定测试身份登录／设置获准 Header：<HEADER_NAME>: <CONTROLLED_FIXTURE>／明确不设置身份 Header>。
2. 新建 Session。
3. 发送：<Agent 准备的完整请求>。
4. 检查预期调用=<TOOL_NAME> 是否实际发生；如未调用，保留结果并回复，不反复发送制造副作用。
回复：`session_id=<ID>；message_id=<助手消息 ID>；log_id=<LogID 或 not_returned>；result=<脱敏原始结果摘要>`
```

**回读与判定：**

- Agent 查询实际 Session 的历史／debug，提取 Tool 请求响应、run 和日志关联；找不到消息时先按时间和会话信息查实际新 Session，不直接要求用户重做。
- 用 LogID 关联后端版本及脱敏身份证据。日志为空时核对查询范围，必要时检查实例实际日志列表，避免硬编码轮转文件名造成假缺失。
- 按真实 Tool 返回和权威业务状态判断；Host 文本声称成功不替代执行结果。受控 Header fixture 只能证明其覆盖的传输／归属／隔离，不能冒充真实账号认证验收。
- 若会话恢复或查询替代了预期写调用，记录实际覆盖及 `known gap`，不宣称验证了写重放，也不反复要求同一无效操作；缺口是否接受由验收决策者确认。

## 登录审批与权限协助

**准备：** 先按当前技能排查登录／权限错误，查询已有工单和状态；确认真正需要的资源、权限、期限、申请理由及审批入口。Agent 不索要用户凭证，也不把 403 当作重新登录即可解决。

```text
### 事项：<登录／审批／权限申请>
入口：<官方登录入口、审批单 URL 或权限申请入口>
操作：
1. <在当前会话完成官方登录／核对审批单=<ID>／填写明确资源与最小权限范围>。
2. <仅执行本次授权的申请或审批动作；申请理由、期限等完整字段由 Agent 给出>。
3. 保留结果，不复制 JWT、Cookie 或验证码。
回复：`状态=<已登录／已提交／已批准／blocked>；ticket_or_url=<可用工单或 URL／not_returned>`
```

**回读标准：** 登录后重试原必要查询；审批后回读原工单和权限生效状态。提交申请不等于批准，批准也不替代实际资源访问验证。仅当当前技能明确要求用户运行交互命令时，给出其官方命令并建议用 `! <命令>` 在本会话执行，不猜登录参数。

# 平台操作与证据

本页是平台工具、授权和证据归属的唯一约定。流程手册不构成创建资源、构建、发布、部署、删除或切换环境的授权。

## 执行顺序

1. 从本次需求和目标配置定位仓库、分支、资源与环境；能查明的事实自行查明。缺少关键输入时先完成其他独立事项，再说明阻塞。
2. 加载当前可用的平台技能并查看目标命令的 `--help`，核对 CLI 支持范围。历史文档是流程参考，当前工具及平台响应才是参数与能力依据。
3. 写入前取得目标、影响范围与恢复边界的明确授权；已有授权仅适用于其约定范围。工具支持时先 dry-run／pre-check，再按其确认要求提交。
4. 保存响应并回读原资源或原任务。完成标准：目标一致、终态明确、实际配置符合预期；请求提交或页面提示成功不替代回读。
5. 记录证据与未覆盖项。结果不明时继续查原任务；恢复前先定位最早失败阶段，避免并行重复提交。

## 内部研发平台

使用当前 `bytedcli` 技能，按其路由加载领域说明：仓库与 MR 走 Codebase；研发任务与流水线走 BITS；部署走 TCE／ENV；接口定义与分支产物走 BAM／Overpass；验收、日志和监控走对应测试及观测能力。官方资料查询使用该技能提供的文档入口。

优先已安装的 `bytedcli`；结构化输出使用域前全局 `--json`。安装、升级和权限变更另行确认，不作为文档初始化的副作用。仅查看本地帮助时可按当前技能使用 `--no-auto-upgrade` 避免自动升级。

## MIA 工具

操作 MIA 前加载当前 `miacli` 技能及对应分支：Agent、Component／Skill、Workflow、观测、评测、指标、数据集或场景。仓内有 `miacli/` 时先按其 `AGENTS.md` 使用本地 CLI；否则按已加载技能指定的固定版本 npm 前缀执行 `pony-mia`。

本项目不复制技能安装路径、固定包版本或完整 CLI 手册；以当前技能为准。命令帮助与只读查询示例中的 `pony-mia` 表示上述解析后的 CLI。需要结构化输出时使用全局 `--output json`。

- 直接执行必要的业务查询，由当前 CLI 完成认证；不要预先要求手动登录。登录／权限失败按技能处理，凭证原文不进入文档或证据。
- MIA 操作仅走 `pony-mia` 已暴露的能力；CLI 不支持时明确标为“不支持”，将必要步骤交给获授权人员使用平台正式入口。以平台响应或 CLI 回读验证结果，不拼 HTTP、不直连私有接口或换工具绕过 CLI。
- 查询、草稿修改、发布和真实运行是不同动作；按本次目标界定完成点，不因保存草稿而顺便发布、运行或评测。

## MIA 上下文

本项目的 MIA 空间、app／scene、稳定路由和数据面环境均待首次实施确认。

1. 从用户链接、目标配置或平台查询定位空间和资源，保留链接中的 `space_id`、`motif_id`、`agent_id`／`graph_id`，有 `session_id` 时也保留。
2. 用 `space list`、`context show` 和必要的场景查询核对可访问资源；CLI 默认空间或本机已保存上下文不代表本项目目标。
3. 空间或上下文不符时先确认切换安排；`space use`、`context create/use` 会改变 CLI 本地配置，不作为只读检查执行。
4. 分别确认管理上下文与 SDK／服务调用的数据面环境，不由一个推导另一个。命令要求的资源 ID 仍显式传入，context 不自动补齐。

完成标准：本次操作空间、资源和数据面目标均可核实，后续命令不会误用其他项目上下文。

## 配置与动态证据

稳定服务身份、路由、契约和受管配置在确定后维护于本仓；凭证和本地环境配置按忽略规则保存。当前缺少平台标识时写“待确认”，不根据仓库名或相邻服务猜测。

动态资源 ID、commit、构建／部署版本、revision、graph、Session、run、LogID 和 trace 写入本次实施工单；读写 `.scratch/` 前参阅[任务跟踪约定](../agents/issue-tracker.md)。工单中的历史 ID 可作为定位既有资源的输入，但执行前必须重新回读，不充当最新状态或默认配置。

证据至少包含：目标与授权范围、变更前基线、本次响应、终态回读、验收断言、未覆盖项及恢复入口。版本与乐观锁值来自响应，不用 `+1` 推导。平台未返回某类标识时记为 `not_returned`，不以其他 ID 代替。

## 人工交接

先完成当前官方工具支持且已获授权的事项；确实需要真人登录、审批或 CLI 缺失能力时，按依赖批次交接。互不依赖的事项同批处理，依赖上一批返回值的事项下一批处理。

每项给出 `事项`、`入口`、`操作`、`回复`：提供已核实入口、完整可粘贴字段、保存草稿或发布的明确动作，以及需要返回的 ID／版本。用户不用推导参数；回复后立即回读，仅交接仍未生效的字段。入口或字段尚不确定时明确说明，不能编造页面路径。

判断需要人工协助或准备交接消息时，读取[人工协作场景与模板](human-handoff.md)：包含 RPC Version、Workflow snapshot、Skill／Tool 发布、Host 后继草稿、真实入口身份验收及登录／审批的触发条件、准备、消息与回读标准。

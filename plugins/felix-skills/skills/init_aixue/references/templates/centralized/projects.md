# 集中式项目归属

协调主仓的 `projects.json` 是正式项目登记，保存主仓名、明确的服务仓集合与源路径。它用于创建工作区；开发 Session 的跨仓路径以 `projects.local.json` 绑定为准，见[工作区手册](workspaces.md)。

- 主仓：统一 README／代理入口、开发发布手册、需求和工单、跨仓术语／ADR 及共享契约。
- 子仓：各自源码、语言与生成配置、构建入口、测试及本服务部署配置；RPC IDL 权威来源按实际项目决策确认。
- 源码与中央文档分别提交。跨仓需求记录每仓 commit／MR、固定依赖、部署和验收结果，不用一个仓库提交代替全部交付。
- 子仓代理入口指向当前工作区同级主仓；默认检出路径不一致时先核实，不能凭项目名称造链接。
- 不重复维护中央工单或跨仓契约；各服务构建输入可复现，不依赖相邻 checkout 的未发布文件。

新初始化默认需求和工单按[本地任务跟踪](../agents/issue-tracker.md)在主仓维护，分诊按[角色约定](../agents/triage-labels.md)，领域按[领域文档](../agents/domain.md)。已有其他真源时保留并同步入口，避免形成平行规范。

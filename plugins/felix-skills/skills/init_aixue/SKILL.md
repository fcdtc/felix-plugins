# 初始化爱学 harness

显式调用后初始化目标仓库的 `docs/development/`，不是文件系统根 `/docs`。默认只写仓内文档；集中式额外交付 workspace 配置、脚本与测试。初始化不安装依赖、不创建真实 worktree、不切换分支、不提交／推送、不操作平台。

## 1. 定位与选择

解析用户参数中的目标路径、`standalone`／`centralized` 形式及项目清单；未给目标时使用当前仓库。读取适用的 `AGENTS.md`／`CLAUDE.md`，核对 Git 根、工作树、现有 README、文档、项目登记和分支约定。保留原有修改和符号链接关系。

- **独立式**：文档、工单和代码归本仓；读取[独立式适配](references/standalone.md)。
- **集中式**：协调主仓集中维护文档、工单与跨仓领域约定，服务子仓独立维护代码；不是 monorepo。读取[集中式适配](references/centralized.md)，明确允许修改的子仓清单后才能跨仓写入。

形式有明确参数或现有约定时直接使用；仍无法判断才询问。项目名称、PSM、平台资源与子仓集合从配置／查询核实，不扫描相邻仓库自动纳管。分支默认 `codex/dev`；已有约定冲突时先确认，集中式允许在项目配置显式选择其他分支。

完成标准：目标身份、形式、分支策略及允许写入范围明确；缺失资料只阻塞依赖它的文件，继续准备其他独立内容。

## 2. 生成与合并

模板索引见[模板及适配规则](references/templates.md)。先读取拟使用模板和目标已有文件，再选择工具或手工合并：

```sh
python3 <SKILL_DIR>/scripts/initialize.py --target <REPO> --mode standalone
python3 <SKILL_DIR>/scripts/initialize.py --target <COORDINATOR> --mode centralized --project-config <CONFIRMED_JSON>
```

默认只输出 JSON 计划；确认计划与本次请求一致后追加 `--apply`。工具只创建缺失文件，已有内容相同则 `unchanged`，不同则 `preserved`，不覆盖；`preserved` 是待语义核对项，不是失败或已完成迁移。工具不是替代 Agent 阅读／判断的合并器。

1. 从内部模板生成开发环境、平台操作、后端构建发布、MIA Agent、RPC 接入及完整人工交接手册。把可核实的本项目约定写入，未知资源保留待确认；已有服务不沿用“尚无代码”等初始化断言。
2. 基础工单／分诊／领域规则仅在缺失时采用模板；已有其他 tracker、状态词表或多上下文规则保留，不静默改成本地 Markdown／single-context。
3. 按所选形式合并 README 导航和精简代理入口。已有 CLAUDE／AGENTS 真源编辑其真源；符号链接保持，双文件已有时遵守各自职责。工具只在两者均不存在时创建 `AGENTS.md`，其他情况由 Agent 增量合并。
4. 集中式安装完整脚本、测试、项目登记和本地绑定忽略规则；读取[集中式适配](references/centralized.md)处理主仓与子仓。子仓只加中央入口指针，不复制中央工单或领域真源。
5. 已有文件逐项比对目标语义：只补缺失导航／步骤，保留自定义规则。同名脚本不直接替换；先检查版本与行为，发生真实设计冲突时才询问处理方式。重复调用不得追加重复章节。

完成标准：计划中每个文件已创建、保持一致或完成保留内容的语义核对；每个保留冲突都有明确处理结果。未解决的真实决策列为阻塞，不声称全部初始化成功。

## 3. 验证与交付

运行[验证清单](references/verification.md)。集中式脚本测试只使用真实临时 Git 仓库，不在用户业务仓创建／删除工作区；脚本就绪不等于工作区已创建。

检查所有生成文档的相对链接、标题锚点、无来源项目身份残留、分支与项目形式一致，以及无缺失脚本入口。人工交接手册必须保留六类业务场景与登录／审批模板，不退化成通用原则。

完成标准：本地测试和文档检查结果明确；现有修改未覆盖，未做外部写入。汇报目标、模式、创建／合并／保留文件、测试结果及真实阻塞；平台绑定未验证时明确不宣称 push 已可部署。

# 记录与计数规则

## 数据来源

| 平台 | 完整记录 | 辅助索引 |
|---|---|---|
| Claude Code | `${CLAUDE_CONFIG_DIR:-~/.claude}/projects/` 中的会话 JSONL | 配置根的 `history.jsonl` |
| Codex | `${CODEX_HOME:-~/.codex}/sessions/` 和 `archived_sessions/` 中的 JSONL／JSONL.zst | 配置根的 `history.jsonl`、`session_index.jsonl` |

使用实际环境覆盖默认根；脚本也接受显式根路径。Claude 的 `sessions/` 通常是进程和运行状态，不替代 `projects/` 中的正文。Codex 输入历史可能缺失最近消息，因此索引只用于核对，不作为完整记录来源。出现脚本不支持的格式时报告缺口，不臆造支持。

以**每条消息的时间戳**筛选统计范围。扫描旧日期目录和归档，包含范围之前开始、范围内续聊的会话；文件的创建时间、修改时间及目录日期只描述存储位置。

## 用户输入识别

### Claude Code

主会话 `type=user` 的文本是候选，不代表全部来自人：工具结果也存在于 user 记录中。核对 `isMeta`、`isSidechain`、`origin`、`sourceToolAssistantUUID`、正文块类型及目录位置。

- 人类问题、需求、确认和显式斜杠命令是实际输入；保留命令名称与参数，剥离加载的 Skill 正文。
- `tool_result`、自动环境提示、压缩续聊摘要、后台通知、子代理输入和中断标记属于系统活动。
- UUID／prompt ID 等稳定标识可用于去除重存副本；不同实际输入即使文字相同也保留。

### Codex

同时检查 `response_item` 的 `role=user` 与 `event_msg` 的 `user_message`。同一输入可能在两类事件中各存一份，按稳定消息标识或相邻对应关系去重；单纯全局按文本去重会误删真实重提。

环境、AGENTS 指令、加载的 Skill、应用页面元数据、`Side conversation boundary.` 线程边界提示、父会话继承副本和 Guardian／子代理记录不计入真实输入。`client_authored=false` 不能单独决定删除：实际人类输入也可能带此标记。

用户主动打开的侧会话有独立会话 ID 时单独计数；系统委派子代理不计数。分叉记录中继承的父消息不能再次计入侧会话；来源不明确时列疑似项，核对线程元数据及相邻上下文，不凭会话标题猜测。

## 报告边界

- 唯一会话键为“平台＋会话 ID”，缺失 ID 时内部以日志路径回退；报告中的 session_id 写“未记录”，不展示路径。
- 总输入数包含重提和确认，用于内部审阅完整性检查，不输出统计表；问候与纯控制命令不构造工作主题。
- 内部保留每条摘要对应的平台、会话 ID、文件及行号，用于核对；报告只在推进脉络列出真实完整 session_id，不展示其余来源信息。表格中的 `|` 和换行需转义。
- 推进节点时间取范围内实际消息时间。助手自述未经核验不写成“已完成”；本 Skill 不执行原问题。
- 文件覆盖、固定截止及读取失败用于内部检查。影响可靠性的缺口在报告正文之外的交付回复中说明，避免正文承诺完整覆盖。
- 最终报告结构和字段以[统一报告模板](summary-template.md)为唯一依据。

# Note Lint Skill — 知识库体检（只报不改）

铁律：**本 skill 全程只读，只输出报告，绝不修改、移动、重命名任何笔记文件。** 修不修、怎么修，一律由用户决定——这是「LLM 管结构建议，人管内容」原则在体检上的形态。

规范来源：[`note/vault-conventions.md`](../note/vault-conventions.md)（标准形状、矛盾标注格式）。

## Usage

```
/note-lint              结构层体检（秒级）
/note-lint --semantic   结构层 + 语义层（LLM 抽样精读，较慢）
```

## Behavior

### 1. 结构层（必跑，脚本零成本）

```bash
bash /Users/congfei/.claude/skills/note/scripts/lint.sh [vault]
```

报告七项：frontmatter 缺字段 / 重名冲突 / 死链 / 孤立笔记 / 索引新鲜度 / 多块缺目录 / 矛盾标注现状（信息项）。

**完成标志：拿到完整结构报告，向用户复述问题要点（不是贴原文，是归纳）。**

### 2. 语义层（仅 `--semantic` 时）

全库精读不现实，按三类**抽样策略**选笔记对，每类读 2-3 对：

| 找什么 | 怎么选样 | 来源 |
|--------|---------|------|
| **矛盾** | 同一标签下、不同目录的两篇 | INDEX 标签聚类区 |
| **过时结论** | 标题主题相近、结论可能已演进的两篇（如「X」与「X 再思考」） | INDEX 目录区 |
| **意外关联** | 同一枢纽的引用者中主题最不相似的两篇 | INDEX 枢纽区 |

`Read` 选中的笔记对，对照两篇的结论与前提。

**完成标志：三类各给出结论（含"未发现"），每个发现都有笔记对、原文依据和建议。**

输出格式：

```markdown
# 📋 知识库体检报告（{日期}）

## 结构层（{N} 项）
- {归纳后的问题要点，含文件名}

## 语义层（--semantic 时）
| 类型 | 笔记对 | 发现 | 建议 |
|------|--------|------|------|
| 矛盾 | [[A]] × [[B]] | {各自结论} | 拟 ⚠️ 标注文案（见下），是否写入由你决定 |
| 过时结论 | [[A]] × [[B]] | … | 修订/归档建议 |
| 意外关联 | [[A]] × [[B]] | … | 建议在相关笔记区互链 |

## 矛盾标注（拟写入文案，待用户确认）
- [[A]] 的相关笔记区：`- [[B]] — ⚠️ 结论冲突：…`
- [[B]] 的相关笔记区：`- [[A]] — ⚠️ 结论冲突：…`
```

语义层发现矛盾时给出拟写入双方的 ⚠️ 标注文案（格式见 conventions「矛盾标注」），**报告完即止**——用户若确认，再手动加或让 `/note` 流程处理。发现孤岛/死链等结构问题需修复时，提示用户跑 `/note` 或 `update-wiki.sh`，本 skill 不代跑修复性写操作。

## 边界

- 索引过时（lint 报告第 5 项）→ 提示用户跑 `update-wiki.sh`，不代跑
- 语义层发现的不止矛盾：重复笔记可建议合并、断链主题可建议互链——都是**建议**，动作归人
